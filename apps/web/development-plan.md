# План frontend

Выполнять по одной ролевой карточке и останавливаться на ревью. Обязательны [AGENTS](AGENTS.md), [общий порядок и значение галочек](../../docs/agent-workflow.md), [backlog](../../docs/product/backlog.md). ID ниже — существующие карточки; слово «web» выделяет только свою часть, не новый ID. Все зависимости backlog действуют. По завершении заполнить запись доказательств по общему порядку.

Источники: [web-правила](../../docs/architecture/web-conventions.md), [API](../../docs/architecture/api-contract.md), [identity](../../docs/architecture/authentication.md), [адреса](../../docs/architecture/publication-addresses.md), [макеты](../../docs/design/README.md), [QA T/P/R](../../docs/qa/test-plan.md), [FR/NFR и критерии](../../docs/product/acceptance-criteria.md). Дизайн-пакеты ниже описаны в [дизайн-плане](../../docs/design/development-plan.md).

## Вход: общий каркас E1-00 → E1-01

Не создавать свой монорепозиторий параллельно backend. Сначала принятый общий [E1-01](../../docs/product/first-task.md): npm workspaces, Next, Nest, страница, `/health`, реальные typecheck/build. Проверяет интегратор по T-01–06. Отдельного завершённого web-каркаса это не заменяет.

- [ ] Принятый общий каркас доступен в main; записан SHA и проверен запуск web.

## E1-04 / E1-04b · Web регистрации, входа и кабинета

Вход: принятые API регистрации/сессии и дизайн «Кабинет и identity»; Q-11 для зависимых правил. При необходимости разделить регистрацию и вход на отдельные поручения/PR. Результат: Mantine через shared/ui, CSS variables/light-dark, основа next-intl, формы, выход, приватная навигация. Сначала согласовать OpenAPI → Orval и владельца `packages/api-client`; клиентские и server-only методы разделены. Не ставить весь будущий стек без потребителя.

Приёмка: FR-02/03, NFR-07; ошибки полей, loading, 401, очистка приватного Query cache при logout, нет доступа A к данным B. Проверки: Vitest значимого поведения, browser/manual mobile/темы/локали и интеграция с реальным API; реальные typecheck/build.

- [ ] Web-результат реализован и проверен; доказательства записаны.
- [ ] Владелец принял web-результат.
- [ ] Web-результат проверен в main; SHA записан.
