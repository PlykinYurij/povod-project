# Пользовательские сценарии

Основание: [ТЗ §1, §5–6 и §14](../povod-mvp-spec-v0.1.md#6-функциональные-требования-и-критерии-приёмки). Статусы: [README](README.md). Это описание поведения, без экранных макетов и API-контрактов. Неопределённые ветки связаны с [вопросами](open-questions.md).

| Поток | Предусловие и основной путь | Ошибки и альтернативы | Ссылки |
| --- | --- | --- | --- |
| UF-01 Выбор | Посетитель без аккаунта смотрит каталог и демо, выбирает шаблон и начинает регистрацию | Демо не сохраняет реальные ответы. Что сохраняется из выбора после входа — определить в UX; недоступность сервиса не выдаётся за успешное создание | FR-01/05 |
| UF-02 Аккаунт | Пользователь регистрируется/входит; после авторизации дополнительные подтверждения для создания и публикации не нужны (D-02). Выход отзывает сессию; reset восстанавливает доступ | Неверные данные, истечение сессии, лимиты, ошибки восстановления. Вход/reset не раскрывают наличие email; токены восстановления одноразовые | FR-02–04 с уточнением D-02; NFR-07 |
| UF-03 Черновик | Авторизованный владелец выбирает шаблон, создаёт приватный проект, вводит данные, добавляет фото, видит результат сохранения и приватный предпросмотр | Квота черновиков (Г), невалидные поля, сбой/обработка фото, потеря сети, конфликт вкладок. Старая версия не затирает новую; ошибка видима. Чужой идентификатор не даёт доступа. Возврат после истечения сессии не должен молча сообщать о сохранении | FR-05–10; Q-03/08 |
| UF-04 Первая публикация | Авторизованный владелец проверяет предпросмотр, выбирает доступный бесплатный тариф, видит дату отключения, публикует, копирует ссылку и отправляет самостоятельно | Неполные поля, фото не готовы, квота двух активных, повтор/конкуренция запросов. Событие позже отключения: предупредить, не запрещать автоматически. Успех копирования показывать только после успеха | FR-11/13/14; Q-01/03 |
| UF-05 Обновление | Владелец меняет черновик, проверяет его и явно публикует новый снимок | До публикации гости видят прежний снимок; сбой оставляет его доступным. URL сохраняется. Срок не продлевается (П, D-01) | FR-08/11/12 |
| UF-06 Гость | Гость открывает действующую ссылку, заполняет имя/псевдоним и анкету, отправляет и видит подтверждение | Невалидные значения, отказ от участия (Q-04), лимит 300, потеря ответа сети, повтор запроса. Истечение/блокировка между открытием и отправкой запрещают запись. Одинаковые имена допустимы. Смена формы во время заполнения — Q-04. Самостоятельного исправления нет (D-04); при отказе сопровождающих ноль | FR-15/16 |
| UF-07 Ответы | Владелец открывает список, фильтрует участие, видит счётчики, экспортирует CSV; ошибочную запись удаляет с подтверждением | Чужой аккаунт не получает список/CSV. Удаление освобождает квоту, не меняет другие ответы. По D-04 гость после удаления отправляет заново; старые ответы могут удалиться в новом периоде — дата должна быть понятна владельцу | FR-17–19; Q-01/04 |
| UF-08 Пауза и истечение | Владелец снимает сайт → публичный доступ прекращается, расход срока остановлен. Повторная публикация продолжает остаток. Полное истечение — отдельный путь восстановления | Пауза не выдаёт новый полный срок. Контент/ответы сохраняются до возобновления (D-06); квота/тариф/даты хранения после паузы — Q-01. Блокировка и удаление не дают обычного восстановления; административные переходы — Q-05 | D-05, FR-20–22; уточнение §5 |
| UF-09 Удаление | Владелец подтверждает удаление проекта или запрашивает удаление аккаунта; доступ отзывается, очистка следует утверждённой политике | Удалённый проект нельзя оживить публикацией. Окно отзыва HTML против «сразу» — Q-06; сроки очистки/бэкапов — Q-10. Вариант подтверждения необратимого действия определить в UX | FR-21/22 |
| UF-10 Обращение и администрирование | Обращение поступает superadmin. Администратор снимает сайт с паузой срока или без паузы; режим и причина фиксируются в аудите | Обычный пользователь не вызывает admin. Без паузы срок идёт, с паузой остаток сохраняется. Доступ владельца после снятия — Q-05; неотправленное обращение не показано успешным | D-07, FR-23/24 |

Сквозные условия: RU/EN сервис и кабинет (Т), RU приглашение/анкета; выбранная локаль сохраняется (FR-25). Ключевые действия доступны с телефона и клавиатуры (NFR-01/06). Сохранение, публикация и отправка ответа имеют различимые успех, ожидание и ошибку; конкретные экраны и тексты — следующий этап UX.
