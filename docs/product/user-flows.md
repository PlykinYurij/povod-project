# Пользовательские сценарии · MVP v2

Источник: [MVP v2](mvp-v2.md), D-38/39; FR/NFR исходного [ТЗ](../povod-mvp-spec-v0.1.md) не перенумерованы. UF-ID сохранены, изменённые потоки указаны явно. Предложения и вопросы не считаются принятыми.

| Поток | Основной путь | Ошибки / незакрытые условия | Основание |
| --- | --- | --- | --- |
| UF-01 Каталог | Посетитель выбирает категорию, видит шаблон/фиксированную цену и демо, выбирает самостоятельное создание или помощь | Пустая категория, каталог недоступен, шаблон снят с каталога; существующий проект не должен потерять свою версию | FR-01/25, D-39 |
| UF-02 Identity | Регистрация email/userName/пароль → код → подтверждение/сессия. Обычный login без кода; reset по коду с отзывом сессий | Неверный/истёкший код, resend, лимиты, сеть; pending не User и не owner | FR-02–04, D-28–35 |
| UF-03 Черновик | После входа создать проект из фиксированной версии, заполнить типизированную форму, заменить тексты/фото, сохранить и открыть preview | Длины D-37, пять draft, upload/processing/failed, 401, сеть, conflict двух вкладок. Не выдавать локальные изменения за сохранённые | FR-05–10, D-15/36/37 |
| UF-04 Заявка на публикацию | Из preview клиент открывает контактную форму, отправляет имя/телефон/канал и связь с собственным проектом; видит подтверждение заявки | Ошибки полей, повтор/потерянный ответ, чужой projectId, изменённая revision/цена. Заявка не делает URL публичным | FR-11/14 изменены D-38, R2-03/08/09 |
| UF-05 После публикации | Клиент получает готовый публичный URL; содержимое соответствует одобренной admin версии | Порядок исправлений/снятия/повторной подготовки Q-29; прежнее разрешение только текстов не расширено молча | FR-12, D-17/36/38 |
| UF-06 Гость | Открыть доступное приглашение, заполнить RSVP, отправить и увидеть подтверждение | Ошибки ввода, отказ/companions=0, лимит 300, повтор, снятие/истечение между открытием и submit; форма Q-04 | FR-13/15/16 |
| UF-07 Ответы | Владелец читает/фильтрует свои ответы и выгружает XLSX; неверный ответ удаляется с подтверждением | Чужой доступ запрещён; экспорт после истечения и guest-assisted доступ требуют политики Q-25/26/19; admin contact request не RSVP | FR-17–19 |
| UF-08 Пауза/срок | Публичная доступность и право публикации проверяются сервером | Клиент не выполняет publish/resume; снятие, срок, перерасход/возобновление требуют Q-26/29. Дата события не назначает срок автоматически | FR-20, D-38 |
| UF-09 Удаление | Подтверждённый запрос удаления отзывается и очищается по принятой политике | Контакты заявок, проекты, фото, RSVP и бэкапы имеют разные объекты хранения; Q-10/19. Реализация удаления не объявлена готовой | FR-21/22 |
| UF-10 Admin обработка | Admin открывает очередь, читает контакты/проект, общается с клиентом, проверяет preview, согласует условия, задаёт адрес и публикует | Не-admin 403; занятый адрес, stale revision/заявка/цена, неготовые фото/RSVP, конкурирующие операторы; аудит | FR-24 расширен, D-38 |
| UF-11 Общая заявка | Клиент просит помощь, отправляет контакты без projectId | Нужен ли вход Q-24; поля/частота/idempotency до реализации. Не создавать пустой фиктивный проект или User | D-38, R2-04 |
| UF-12 Admin создаёт за клиента | Из общей заявки выбрать шаблон, заполнить типизированную форму, сохранить/просмотреть, связать проект, согласовать и опубликовать | Владение без аккаунта Q-25, цена после выбора Q-27, повтор создания не дублирует проект, отсутствие связи запрещает publish | D-38/39, R2-06/07 |

При отправке любой формы ввод сохраняется при ошибке; успех показывается после реального ответа сервера. При неопределённом исходе не создавать новый key автоматически. Недоступный шаблон/несохранённая revision не должны маскироваться как готовая публикация. Смена шаблона проекта по D-09 по-прежнему не разрешена.

Мессенджеры — ручная связь администратора с клиентом. Автоматическая отправка сообщений/писем от имени владельца не добавлена и этой аналитикой не выполняется. [UX-разбор](../design/priglashay-reference.md), [проектируемый контракт](../architecture/assisted-publication.md).
