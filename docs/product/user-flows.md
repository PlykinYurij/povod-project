Сквозные условия: RU/EN сервис и кабинет (Т), RU приглашение/анкета; выбранная локаль сохраняется (FR-25). Ключевые действия доступны с телефона и клавиатуры (NFR-01/06). Сохранение, публикация и отправка ответа имеют различимые успех, ожидание и ошибку; конкретные экраны и тексты — следующий этап UX.

## Последовательность владельца: шаблон → публикация

1. Без аккаунта посмотреть каталог и демо, выбрать один из четырёх шаблонов (FR-01). Если вход нужен, войти по email/паролю или зарегистрироваться; после авторизации нет дополнительного подтверждения (D-02). Сохранение выбора после входа рекомендуется для удобства, но пока не принято как обязательное правило.
2. Создать приватный черновик (FR-05). В первой свадебной вертикали заполнить имена, дату/время с поясом и место; фото и программа опциональны (D-03). Увидеть ошибки полей и результат сохранения (FR-06–08).
3. При добавлении фото отдельно дождаться загрузки и завершения обработки. Успешная передача файла не означает готовность фото к публикации (FR-10/11). Ошибка файла, сети или обработки видима; рекомендации UX — повторить либо явно убрать неготовое необязательное фото, а не молча исключать его из снимка.
4. Открыть приватный предпросмотр нужной ширины (FR-09), выбрать доступный бесплатный тариф, увидеть срок публикации и явно опубликовать (FR-11). Длительность тарифа ещё Г, не обязательно 90 дней.
5. Получить общую ссылку и подтверждение успешного копирования (FR-13/14). После публикации правки закрыты (D-10); возможное исключение для опечаток — Q-16.

Потеря сессии при сохранении/загрузке не показывается как успех. После возвращения нужно сверить фактическую сохранённую версию; сохранение локального ввода при этом — рекомендация UX. Превышение квоты, незавершённое фото, конфликт вкладок и ошибка публикации не должны повреждать действующий снимок (FR-08/10–12, NFR-10). Публикация одновременно с очередной правкой требует явно выбранной ревизии — детали согласовать в проектировании, не публиковать непроверенную смесь данных.

## Последовательность гостя: общая ссылка → RSVP

1. Открыть ссылку без аккаунта. При действующей публикации получить опубликованный контент и её анкету; при недоступности перейти в отдельную ветку ниже (FR-13/15).
2. Указать имя/псевдоним, участие и включённые вопросы. При отказе сопровождающих ноль (D-04). Показать ошибки до ложного подтверждения; сервер проверяет значения независимо от клиента.
3. Отправить ответ. Только принятый ответ даёт подтверждение. Потеря сети после принятия требует безопасного повтора того же запроса без второй записи (FR-16). Имя не используется для устранения дублей между разными людьми.
4. На лимите 300 записей новый ответ не сохраняется, существующие остаются. Пауза, истечение или любой режим admin-снятия между открытием и отправкой запрещают новый ответ. Анкета после публикации фиксирована (D-10).

Рекомендация UX: сохранять совместимые введённые значения при исправимых ошибках. Поведение повтора уже принятого запроса после закрытия сайта или удаления его записи владельцем ещё требует Q-11; нельзя незаметно воскресить удалённый ответ. Самостоятельного исправления гостем нет (D-04).

## Недоступность, архив и ответы

Несуществующая ссылка, удалённый проект, истечение, пауза владельца, admin-снятие с паузой и без неё — отдельные проверяемые причины недоступности. Публичная сторона не раскрывает черновик, персональные данные и внутреннюю причину санкции; нейтральная страница не принимает новую анкету (§5). Точные тексты и различимость причин гостю — задача UX.

В кабинете нельзя смешивать «истёк срок» и «снят с паузой»: для паузы сохраняется остаток, для истечения остаток исчерпан. Данные при этом могут ещё храниться. После admin-снятия владелец сохраняет чтение/CSV и сам возобновляет сайт (D-08); публичная недоступность не означает удаления данных.

Список ответов имеет загрузку, пустой результат, ошибку и данные; пустой фильтр отличается от отсутствия ответов. Удаление ошибочной записи требует подтверждения и освобождает квоту; удаление последней записи возвращает пустое состояние (FR-17–19). Поведение пустого CSV и сохранения фильтра при экспорте согласовать для функции ответов, не считать принятым.
