# E2-02d · Серверные права администратора

Требования: FR-24, NFR-07–10, R2-05, D-38/41/42. База main 3626e47 + зависимая документация 034c495; ветка feat/admin-access. Документы ещё не означают owner review/main.

Результат одного PR: role USER/ADMIN в users, серверный AdminGuard, GET /api/v1/admin/access, закрытая локальная команда grant/revoke, OpenAPI → Orval и проверки изоляции. Это основа приватных экранов, не готовая очередь заявок/публикация.

## Контракт

GET /api/v1/admin/access без тела, cookie Session. Успех 200 `{ "role": "ADMIN" }`; 401 AUTH_REQUIRED для отсутствующей/отозванной сессии; 403 ADMIN_REQUIRED для обычного пользователя; 503 SERVICE_UNAVAILABLE для недоступной БД. Все ответы no-store. Не отдаёт email, ORM user, проекты или контакты.

Роль читается из users на каждом запросе, не из cookie/query/Authorization/custom header. SessionGuard проверяет сессию, AdminGuard — актуальную роль. Будущая критическая write-транзакция должна повторно проверить актуальное разрешение под согласованной блокировкой: guard не заменяет owner/project/revision/CSRF и не отменяет уже выполняющийся запрос.

## Критерии приёмки

- [x] Новая аддитивная миграция: существующие аккаунты USER, никто автоматически не повышается; прежние данные и миграции сохранены.
- [x] Регистрация не принимает role/isAdmin; нет публичного маршрута выдачи/отзыва роли.
- [x] Обычный пользователь 403, гость/отозванная сессия 401; admin 200. Подмена роли в запросе не помогает.
- [x] Grant/revoke отражаются на следующем запросе существующей сессии; второй пользователь не получает права.
- [x] Закрытая local-команда требует точный dev/test target, UUID существующего аккаунта и подтверждённый email для grant. Не создаёт аккаунты, отказывает production/remote, не выводит URL/пароли.
- [x] OpenAPI 0.10.0 воспроизводимо генерирует тип/HTTP/hook; web transport разрешает только точный GET access, не произвольные admin paths.
- [x] Typecheck/build обоих приложений, root/web и HTTP/PG проверки прошли: [отчёт](../qa/e2-02d-admin-access-report.md).
- [ ] Ревью владельца.
- [ ] Интеграция в main.

Не входят: admin UI, заявки, публикация, повышение пользователей через UI, production bootstrap/SSO/2FA, постоянный аудит выдачи прав. Последние условия нужны перед публичным выпуском, не выдаются за готовые локальной командой.
