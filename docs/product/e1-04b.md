Статус **Review**: код 51455ea прошёл локальные проверки, hosted CI 44075260483 и полный Windows isolated kit; [QA](../qa/e1-04b-report.md). База main `9c0cc4c`, backend E1-04 принят владельцем. Результат одного PR: server-side Session, login/current/logout, atomic register+session, SessionGuard, cookie/CSRF bootstrap, нейтральные ошибки, лимиты, OpenAPI и миграция. Reset/письма, проекты, UI/Orval consumer, серверный deploy и роль admin — отдельные карточки.

Критерии:

1. Регистрация атомарно создаёт аккаунт и сессию, ставит cookie, возвращает только user.id/email. Сбой создания сессии откатывает аккаунт.
2. Вход выдаёт новый случайный токен, отзывает прежний токен этого браузера. Неверный пароль и неизвестный email — одинаковый 401. В БД только hash session token, не bearer в JSON/URL/localStorage.
3. Cookie сохраняется после закрытия браузера; host-only/Path=/HttpOnly/SameSite=Lax, production Secure и __Host-prefix. Сервер проверяет idle 7 дней и absolute 30 дней, активность не продлевает absolute.
4. GET session аутентифицирует только по cookie и возвращает текущего пользователя. A/B изолированы, клиентский ownerId не меняет actor. Guard не подменяет будущую проверку ownerId проекта/фото/ответа.
5. Logout отзывает только текущую сессию и очищает cookie. Повтор/истёкшая сессия — 204 при валидном CSRF; отозванный токен не аутентифицирует.
6. Register/login/logout требуют Origin/JSON/CSRF. Bootstrap выдаёт подписанный token, связанный с HttpOnly context-cookie и текущей session-cookie. После смены сессии старый CSRF недействителен. Подмена/чужой context/истечение → 403.
7. Register — 5/IP/15 минут; login — 5 неверных/email+IP/15 минут, без постоянного account lock. Login counter атомарен в PostgreSQL, переживает перезапуск/API-инстанцию, успех сбрасывает ошибки, контролируемый infrastructure failure освобождает резерв.
8. Типы/обе сборки/существующие suites, реальные HTTP/PG-проверки времени/конкуренции/отзыва/CSRF и OpenAPI прошли. Чистые CI/kit подтверждаются фактическим SHA, не наличием кода.

Реальные команды, ограничения single-instance registration limiter и ручная приёмка — [sessions runbook](../operations/sessions.md). Публикация приложения и готовность всей identity/web вертикали не следуют из backend Review.
