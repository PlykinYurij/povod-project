# Продуктовые документы «Повода»

Обновлено 5 ноября 2026. Статус: подготовка и аналитика выполнены, документы ожидают ревью владельца. Архитектура, макеты и backlog ещё не подготовлены. Исходник оставлен по прежнему пути и сохранён побайтно.

## Карта и приоритеты

1. Явные решения владельца имеют приоритет. Принятые уточнения: [decisions.md](decisions.md). Изменения продуктовых правил фиксировать здесь со ссылкой на решение после ревью; предложения агента не становятся решениями автоматически.
2. [Исходное ТЗ v0.1](../povod-mvp-spec-v0.1.md) — неизменяемый источник FR/NFR. §2 отдельно называет подтверждённые решения и предложения. Остальной текст — требования рабочей спецификации на ревью, а не доказательство отдельного согласования каждого пункта.
3. Документы ниже — аналитическая декомпозиция источника. При расхождении не выбирать удобную версию: зарегистрировать вопрос, зависимый критерий оставить условным и получить решение владельца.
4. [Предварительный план](../implementation-plan.md) — исторический материал подготовки, не утверждённый backlog. Его очередность уточнена текущим поручением: подготовка → аналитика → архитектура и UX/UI → проверка согласованности → backlog → реализация.

| Документ | Назначение |
| --- | --- |
| [decisions.md](decisions.md) | Решения владельца, уточняющие исходник |
| [concept.md](concept.md) | Аудитория, ценность, границы и гипотезы |
| [user-flows.md](user-flows.md) | Основные шаги, ошибки и альтернативы |
| [business-rules.md](business-rules.md) | Правила с указанием статуса и открытых решений |
| [acceptance-criteria.md](acceptance-criteria.md) | Проверяемые результаты, связанные с FR/NFR |
| [open-questions.md](open-questions.md) | Вопросы, последствия, рекомендации и момент решения |

Обозначения во всех документах: **П** — явно подтверждено пользователем в §2 или в decisions.md; **Т** — требование рабочей спецификации; **Г** — явное предложение или гипотеза; **В** — вопрос. Если предлагаемое правило повторено далее как обязательное, оно сохраняет статус Г до решения владельца. Критерии описывают будущую приёмку и не являются отчётом выполненных тестов.

## Результат анализа

Ведущий сопоставил два отдельных прохода: аналитик описал продукт, сценарии и правила; QA-ревьюер независимо проверил исходное ТЗ на противоречия и пробелы. Оба работали без правок файлов и внешних источников; документы собраны ведущим после получения обоих результатов. Ревью итоговых документов владельцем ещё не выполнено.

Рынок повторно не исследовался; цены, референсы и юридические ссылки из источника не проверялись заново. Фраза ТЗ «репозиторий ещё не создан» устарела: репозиторий существует. Работа идёт в Windows/PowerShell из WebStorm; выбор WSL и менеджера пакетов пока открыт.

## Что понадобится позже

На следующем этапе достаточно локальных документов и прототипов. Figma понадобится только при выборе этого инструмента для совместных макетов; доступ не предполагается. GitHub-интеграция для Issues/PR/Projects — после согласования backlog и разрешения внешних действий. Провайдеры VPS/S3/почты, домены и секреты — перед инфраструктурой. Сейчас эти подключения не создавались. Подходящего обязательного skill для локальной Markdown-аналитики нет; установки skills не выполнялись.
