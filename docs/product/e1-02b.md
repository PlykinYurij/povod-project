# E1-02b · Разобрать audit dev-зависимостей

Статус: Backlog. Обнаружено при проверке E1-04c 18.11.2026; NFR-07/09/14/15 [ТЗ](../povod-mvp-spec-v0.1.md). Роль: разработчик tooling + QA. Зависимость: существующий npm lockfile/CI, согласование существенной смены версий до реализации. Один PR, без расширения auth-задачи.

`npm audit --json` сообщает пять high dependency entries: picomatch → fdir/tinyglobby/vite/vitest. Это одна исходная advisory [GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf), а не пять независимых дефектов приложения. Установлен picomatch 4.0.7 через Vitest 4.1.12. Advisory проверена 18.11.2026: affected <=4.0.7, patched version не указана. Root `npm audit --omit=dev --json` на эту дату: 0 findings. Это ограниченный audit известных зависимостей, не гарантия безопасности runtime.

Результат: оценить возможность передачи недоверенных glob-шаблонов в tooling, проверить актуальное исправление и совместимость; предложить обновление либо ограниченную меру с владельцем. Не выполнять автоматически предложенный downgrade Vitest до 3.1.4 или audit fix --force: это существенное изменение согласованного тестового стека и не доказательство устранения уязвимости.

Приёмка: описаны affected paths и реальная экспозиция, проверены первичные advisory/версии на дату выполнения; согласован минимальный вариант; если обновляются зависимости — точный lockfile, clean npm ci, typecheck/build, 8 artifact unit и все существующие DB/HTTP suites, воспроизводимая Windows/Linux сборка. Если исправления ещё нет — явно зафиксированы ограничение, остаточный риск, срок пересмотра и решение владельца, без заявления «audit зелёный». Версии/результаты записать в QA.
