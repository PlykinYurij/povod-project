## Результат и границы

Уточнение review D-36: все тексты оформления теперь входят в content.copy, а не спрятаны в JSX. RU — язык начального примера; текст владельца не ограничен русским. content.locale независим от кабинета и управляет только служебными сообщениями/форматированием. Пресеты и system messages вынесены в shared/i18n/garden; при чтении сохранённые тексты не подменяются. Форма редактирования всё ещё отдельный этап. [Решение](decisions.md#d-36--все-контентные-тексты-шаблона-редактируются-владельцем).

Серверный компонент GardenInvitation отображает имена, календарную дату/время/пояс и место, опциональные программу/изображение, фиксированный порядок и палитры sage/sand. Свои CSS Modules/variables, системные шрифты и оригинальная SVG-иллюстрация; без Mantine/Query/i18n-провайдеров кабинета. Единственный клиентский участок — загрузка/ошибка картинки.

Демо `/templates/quiet-garden` доступно по ссылке с главной. Это синтетические данные, без проекта, опубликованного приглашения, RSVP и вызовов API. Панель просмотра RU/EN переключает палитру и полный/минимальный/пустой/ожидающий медиа пример; само приглашение RU. Неполный контент показывает честные заглушки, а не выдуманные имена/даты. Название проекта/ownerId/email не передаются в рендерер.

GardenContent — локальная модель отображения, не DTO и не согласованная схема публикации. Q-03 (точные ограничения полей) и Q-04 (анкета) остаются открытыми; до их решения независимый визуальный этап не вводит серверную валидацию, API/БД или новые зависимости. Ведущий запросил принятие существующего предложения A-02, но отсутствие ответа не означает принятие.

Общая E2-01 остаётся незавершённой: shared schema/контракт для backend, проверка публикационной готовности и владелец их приёмки — последующий этап. Каталог/выбор E2-01b, draft API E2-02, редактор E2-02b, настоящие медиа E2-03 и RSVP E3-01/01b не реализуются этим PR. Требование D-16 о форме в первой реальной публикации сохраняется.

## Критерии приёмки

1. Один GardenInvitation пригоден для будущих приватного preview и публичного snapshot; локальная демо-страница подаёт синтетический content, не копирует рендерер.
2. Обе палитры видны; тёмная тема кабинета не меняет приглашение. Нет произвольных цветов и смены порядка блоков.
3. Программа/фото с null не показываются; выбранное неготовое фото не исчезает молча. Loading, успешная картинка и ошибка загрузки различаются; кешированная SSR-картинка не застревает в loading.
4. Дата не сдвигается из-за пояса сервера/браузера; прошедшая дата отображается. Неверные значения не подменяются текущей датой. Route только HTTPS без credentials, тексты экранированы.
5. На 360 и 1280 px нет горизонтального скролла, в том числе для длинного имени; поля панели доступны с клавиатуры. Демо noindex и без реального submit RSVP.
6. Тесты рядом с модулями; types/build/format и значимое поведение проходят. Исходное ТЗ неизменно, нет новых dependencies/infra/API.

## Проверка владельцем

Из корня `npm run dev:web`, затем открыть `http://127.0.0.1:3000/templates/quiet-garden` (либо ссылку на главной). Backend/БД для демо не нужны.

Переключить обе палитры и все четыре состояния, уменьшить окно до 360 px, посмотреть программу и иллюстрацию. Проверить обычный вход в кабинет отдельно — демо не создаёт проект. RU/EN панели наследуется из выбранной локали; приглашение остаётся RU. [Материалы дизайна](../design/quiet-garden.md), [QA](../qa/e2-01a-report.md).

Проверки из корня: `npm run test:web`, `npm test`, `npm run typecheck`, `npm run build`, `npm run format:web`. Browser-проверка реальной production-сборки отдельно от DOM-тестов; результаты фиксируются в QA, не обещаются заранее.
