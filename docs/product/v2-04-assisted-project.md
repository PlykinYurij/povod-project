# V2-04 · Черновик по заявке без аккаунта

R2-06/09/12, D-41/42 и A-01/A-05. [ТЗ](../povod-mvp-spec-v0.1.md) · [Решения](decisions.md) · [Допущения](implementation-assumptions.md).

- Администратор открывает общую заявку на `/admin/projects`, выбирает доступную версию шаблона и вводит название. Черновик создаётся и привязывается к заявке в одной транзакции. Заявка переходит в «В работе».
- У черновика нет `ownerId`. Создатель записывается в `createdByUserId`; удаление администратора обнуляет ссылку на создателя и сохраняет черновик. Миграция заполняет поле создателя у существующих проектов текущим владельцем. Обычные черновики продолжают записывать владельца и создателя при создании.
- Операторский черновик открывается из заявки и не появляется в личном кабинете создавшего администратора. Личная квота черновиков к нему не применяется. Контакты остаются в заявке. Личный аккаунт клиента не создаётся.
- `POST /api/v1/admin/requests/{id}/project` принимает название, версию шаблона и `expectedRequestVersion`. Повтор с тем же названием и версией возвращает текущий черновик, другое тело после привязки получает 409. Новая запись создаётся только для открытой общей заявки. Цена выбранного шаблона фиксируется в заявке, если она настроена.
- `PATCH /api/v1/admin/requests/{id}/project/draft` использует тот же валидатор и проверку ревизии, что личный редактор. Права администратора, CSRF и Origin проверяются для обеих операций. Редактор в админке открывает сохраняемые поля, а предпросмотр меняется после успешной записи.

Для приёмки выполните `npm run db:migrate:dev`, запустите `npm run dev:api:database` и `npm run dev:web`. Оставьте синтетическую заявку через `/request-help`, затем войдите администратором, откройте её, создайте черновик и измените имя в редакторе. Проверьте обновление предпросмотра и отсутствие черновика в личном списке.

Публикация и назначение адреса остаются отдельной задачей. Автоматическая привязка к аккаунту клиента остаётся за рамками этого сценария.

Проверено локально: 172 общих и 226 API/БД-проверок, типы, сборки, форматирование и повторная генерация Orval. Гонка двух POST возвращает один ID, обычный пользователь получает 403, а создатель видит проект только через операторский маршрут. Миграция применена в dev и test. Повтор в test подтвердил отсутствие ожидающих миграций. Первый прогон БД попал на случайный порт, заблокированный Node fetch в suite регистрации. Следующий полный прогон прошёл.

В Chrome с тестовой БД проверены выбор шаблона из общей заявки, создание, редактирование с увеличением ревизии и обновление предпросмотра. Просмотрены ширины 360 и 1280 px.
