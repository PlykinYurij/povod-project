# E3-02 · Просмотр ответов гостей

Для опубликованного проекта владелец в личном кабинете открывает «Ответы гостей». Для приглашения, оформленного для клиента без аккаунта, администратор открывает ответы из карточки связанной заявки. [FR-17](../povod-mvp-spec-v0.1.md) · [Правило владения A-01](implementation-assumptions.md) · [Гостевая анкета](e3-01b-guest-rsvp.md).

- В списке отображаются имя или псевдоним, решение об участии, число сопровождающих и время ответа. Сортировка идёт от новых к старым, при равном времени порядок фиксирован по ID.
- Фильтр «Все / Придут / Не придут» меняет строки. Счётчики показывают все ответы проекта, включая ответы по предыдущим версиям анкеты. Счётчик сопровождающих складывает сопровождающих из самих анкет.
- Доступ сохраняется, если приглашение скрыто до истечения срока. Черновик, чужой проект, удалённая и истёкшая публикации возвращают нейтральный 404. Экран различает отсутствие ответов, пустой результат фильтра и недоступность.
- В админке ответы загружаются после «Показать ответы гостей». Для проекта с аккаунтом этот раздел открывает владелец в кабинете. Самостоятельный доступ клиента без аккаунта остаётся вопросом Q-25.

## Контракт 0.23.0

| GET | Назначение |
| --- | --- |
| `/api/v1/projects/{id}/responses` | Сессия владельца проекта |
| `/api/v1/admin/requests/{id}/responses` | Сессия администратора и связанная заявка типа ASSISTANCE для проекта без владельца |

Оба маршрута принимают необязательный фильтр `attendance=yes\|no`, возвращают `{counts, items}` и задают `Cache-Control: private, no-store`. Счётчики и строки вычисляются из одного согласованного чтения PostgreSQL. Ответ ограничен текущим продуктовым лимитом в 300 анкет, поэтому отдельная пагинация в этой карточке не нужна. Ответы гостей, контакты заявки и ключи повтора остаются разными наборами данных. Миграций нет.

## Проверка

1. Запустите web и API по [инструкции гостевой страницы](e2-04b-guest-page.md#локальный-запуск). Опубликуйте тестовый проект, отправьте один положительный ответ с двумя сопровождающими и один отказ.
2. Откройте ответы в кабинете владельца или в карточке соответствующей операторской заявки. При выборе «Не придут» остаётся одна строка, общие счётчики сохраняются.
3. Проверки доступа, пустого списка, фильтра, сортировки и истечения входят в `npm run test:database` после сборки API. Компонентные проверки входят в `npm test`.

23.11.2026 локально прошли типы, обе сборки, 189 тестов Vitest и 249 проверок HTTP/PostgreSQL. В Chrome на ширине 360 px проверены таблица оператора, переход из кабинета владельца, фильтр при неизменных счётчиках и закрытие списка после истечения. Использованы синтетические ответы в test-БД.

Экспорт XLSX и удаление ошибочных ответов описаны отдельно. [E3-02b](e3-02b-rsvp-export-delete.md).
