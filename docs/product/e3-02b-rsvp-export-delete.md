# E3-02b · XLSX и удаление ответа гостя

В кабинете проекта и в ответах на операторскую заявку можно скачать XLSX или удалить ошибочный ответ с подтверждением. Действуют те же права и срок доступа, что и у [просмотра ответов](e3-02-rsvp-dashboard.md). [D-12](decisions.md) · [FR-18/19](../povod-mvp-spec-v0.1.md) · [QA R-06/07](../qa/test-plan.md#rsvp-следующий-технический-этап-но-до-первого-публикуемого-продукта).

## Экспорт

Кнопка «Скачать XLSX» выгружает все сохранённые ответы проекта. Фильтр участия влияет на экран. В файле один лист «Ответы гостей» с именем, участием, числом сопровождающих и временем в UTC. Даже пустой проект получает файл с заголовками. Значения имени записываются как текстовые ячейки. Начальные `=`, `+`, `-` и `@` сохраняются как часть строки. Вопрос о дополнительном CSV остаётся Q-17.

API возвращает `rsvp-responses.xlsx` с MIME XLSX и `Cache-Control: private, no-store`. Сервер использует `fflate@0.8.3` только для упаковки сгенерированных частей XLSX. [Документация ZIP](https://github.com/101arrowz/fflate/blob/master/docs/functions/zipSync.md).

## Удаление и повторы

Удаление физически убирает строку ответа с именем. В той же транзакции создаётся запись в `rsvp_deleted_keys` с ID ответа, ID публикации и хешем ключа повтора. После commit квота освобождается. Если запрос удаления повторится, API вернёт 204 ещё раз для того же ответа в рамках доступного проекта. Повтор гостевой отправки с прежним ключом получает 409 `RSVP_RESPONSE_DELETED` и квоту не расходует. Публикация, удаление и гостевая отправка используют общую блокировку проекта.

Рабочее допущение по Q-11 — запись ключа сохраняется до физического удаления публикации. FK удалит эти ключи вместе с публикацией. Отдельный TTL/Purge требует решения Q-11/19. Миграция `20261123000000_rsvp_deleted_keys` добавляет таблицу без изменений существующих анкет.

| Маршрут | Условия |
| --- | --- |
| GET `/api/v1/projects/{id}/responses/export` | Сессия владельца проекта |
| GET `/api/v1/admin/requests/{id}/responses/export` | Сессия администратора и связанный проект клиента без аккаунта |
| DELETE `/api/v1/projects/{id}/responses/{responseId}` | Те же права владельца, JSON Origin и CSRF |
| DELETE `/api/v1/admin/requests/{id}/responses/{responseId}` | Те же операторские права, JSON Origin, CSRF и повторная проверка роли в транзакции |

## Проверка

Запустите API и web по [инструкции гостевой страницы](e2-04b-guest-page.md#локальный-запуск). Для ветки с новой миграцией примените `npm run db:migrate:dev`. В тестовом проекте с двумя ответами включите фильтр, скачайте XLSX и проверьте обе строки. Нажмите «Удалить» у ответа, отмените и проверьте, что строка осталась. Затем подтвердите удаление и проверьте обновлённый счётчик. Только локальные синтетические данные.

Браузерная проверка на ширине 360 px прошла скачивание, отмену и подтверждение удаления. Независимый парсер прочитал файл, полученный из браузера, и подтвердил типы ячеек, кириллицу, числовое число сопровождающих и отсутствие формул. Набор `npm run test:database` проверяет права/CSRF, новую отправку после освобождения 300-го места и невозможность восстановить удалённый ответ прежним ключом.

23.11.2026 локально прошли проверка типов, обе сборки, 189 тестов Vitest, 250 проверок HTTP/PostgreSQL, воспроизведение OpenAPI/Orval и миграции test/dev.
