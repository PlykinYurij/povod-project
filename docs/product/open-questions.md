# Нерешённые вопросы

Источник: [ТЗ v0.1](../povod-mvp-spec-v0.1.md). Статусы — [README](README.md). Рекомендации не являются решениями. Реестр объединяет результаты аналитика и независимого QA-прохода; не каждый пробел является противоречием.

## До утверждения архитектуры и UX основного сценария

Вопросы не мешают исследовать альтернативы параллельно, но без ответа нельзя утвердить зависимые модели, переходы и прототипы.

| ID / вопрос | Основание и последствия | Рекомендация ведущего |
| --- | --- | --- |
| Q-01. Нужен ли повторный выбор тарифа при возобновлении оставшегося периода? | D-18 закрывает освобождение места после истечения; D-11 оставляет место занятым на паузе | Предлагается продолжать прежнее право без нового выбора и нового периода. Эффект: простое возобновление; платные сценарии отдельно после MVP |
| Q-03. Каковы точные текстовые поля, длины и дополнительные блоки первого шаблона? | D-14 принимает «Тихий сад» и обязательные название/адрес, D-17 разрешает только тексты после публикации | Предлагается whitelist имён, названия/адреса места, текста пунктов программы без смены пунктов. Эффект: исправление ошибок без изменения структуры/ответов |
| Q-04. Какова небольшая форма каждого шаблона, обязательность её вопросов и счётчики? | D-10 исключает смену анкеты после публикации, поэтому конфликт изменённой формы больше не основной сценарий. Эффект: простой гостевой путь и неизменный смысл ответов |
| Q-05. Как admin-изменение даты влияет на хранение/квоты; что происходит при полном истечении в режиме без паузы? | D-08 разрешает владельцу чтение/экспорт и самостоятельное возобновление. Этот выбор заменяет прежний запрет обхода admin-снятия | Предлагается полный расход срока обрабатывать как истечение независимо от причины недоступности; изменение даты аудировать отдельно от хранения. Эффект: единый понятный расчёт, без автоматического продления старых анкет |

## Расхождения без отдельного вопроса

- «Репозиторий ещё не создан» (§2) — устаревший факт. Исходник не исправляем.
- FR-25 добавляет RU/EN публичного интерфейса к подтверждённому кабинету. Сохранено как Т; противоположного запрета в источнике нет.
- Неизученный Vowee не блокирует собственное проектирование и не подтверждает функции/стиль.

Q-02 закрыт решением D-02: после авторизации дополнительное подтверждение не требуется.

## Эффекты рекомендаций и условия согласования

Для Q-01/03/04/05 эффект указан в таблице: эти решения нужны для утверждения зависимых частей архитектуры/UX. Начать сравнение вариантов можно до ответа; не требуется заранее утверждать каждый технический предел строки.

| Вопрос | Эффект рекомендации / что она не решает |
| --- | --- |
| Q-06 | Ограниченное окно кеша упрощает отзыв, но «сразу» в FR-21 остаётся нерешённым до принятия исключения |
| Q-07 | Один менеджер/ОС дают воспроизводимость; выбор не меняет продуктовые сценарии |
| Q-08 | Учёт логических фото отдельно от производных делает квоту понятнее; хранение версий всё равно требует ограничения стоимости |
| Q-09 | Измеримый TTL задаёт предел доступа к старым URL ценой более частого обновления ссылок |
| Q-10 | Утверждённая политика предотвращает возвращение удалённых данных после восстановления и определяет основания хранения; аналитику на синтетических данных не блокирует |
| Q-11 | Явные TTL/лимиты позволяют проверить повторы и злоупотребления; новые значения не выбраны агентом |
| Q-12 | Фиксированный протокол делает пороги NFR воспроизводимыми; сами пороги не ослабляются |
| Q-13 | Смета/проверка доступов предотвращает выбор недоступных функций и незапланированные расходы |
| Q-14 | Лицензии дают право использовать материалы, наблюдения проверяют гипотезу ценности; отсутствие Vowee не блокирует собственный UX |

Конкретный пробел Vowee (§3/16): в доступных материалах нет содержимого/скриншотов каталога, входа, создания проекта, редактора/предпросмотра, публикации, мобильных состояний и RSVP. Референс подтверждён только как выбранное владельцем направление. Его функции, композиции и тексты не считаются изученными.

Дополнение к FR-16: лимит 300 относится к хранимым записям события, а не к людям или отдельному периоду. Рекомендация для восстановления — учитывать все ещё хранимые записи проекта; не выдавать новую квоту автоматически новым периодом. Доступ после admin-снятия принят D-08; срок законного хранения после истечения требует Q-10.
