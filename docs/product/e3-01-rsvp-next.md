# E3-01 · Первая анкета и API ответа гостя

Это рабочие допущения для разработки и тестов, пока Q-04 и Q-11 открыты. [Решения D-04/16](decisions.md) · [Вопросы](open-questions.md) · [FR-15/16](../povod-mvp-spec-v0.1.md).

- «Тихий сад», форма v1. Имя или псевдоним от 1 до 80 символов после trim. Участие `yes` или `no`. Допустимое число сопровождающих для `yes` — целое от 0 до 2, как в макете. Для `no` сервер принимает только 0. Дополнительных вопросов в первом варианте нет.
- Форма фиксируется для конкретного снимка публикации. POST принимает ID версии формы и UUID повтора. Версия, которую гость не видел, не заменяется сервером автоматически. Проект и форма определяются по сохранённому публичному адресу на сервере.
- 300 — предел хранимых ответов на проект. Смена опубликованной версии или снятие не обнуляют счётчик. Точный повтор того же запроса даёт исходное подтверждение, новое тело с тем же ключом получает 409. Имя не служит уникальным идентификатором.
- Рабочий предел — 30 новых валидных отправок за 15 минут с одного IP на проект. Счётчик хранит HMAC с отдельным ключом окружения. Повтор полученного подтверждения квоту не расходует. Операционные параметры и политика ключей после удаления требуют сверки перед релизом.

## HTTP · OpenAPI 0.19.0

Операции используют `/api/v1/public/invitations/by-address/{slug}/rsvp`, без сессии гостя и с `Cache-Control: no-store`. Методы и модели сгенерированы Orval. E3-01b подключит гостевой transport и передаст `Idempotency-Key` явно в заголовках вызова, чтобы повтор запроса с потерянным ответом использовал тот же UUID.

| Операция | Запрос | Успешный ответ |
| --- | --- | --- |
| GET | Нормализованный slug из адреса | 200 `{formVersionId, schema: "garden-v1", nameMaxLength: 80, maxCompanions: 2}` |
| POST | UUID в `Idempotency-Key`, JSON `{formVersionId, name, attendance, companions}` | 201 при записи, 200 при точном повторе, оба возвращают `{responseId, receivedAt}` |

Гость получает только поля контракта формы и квитанции. POST отклоняет неизвестные поля, числа в строках, управляющие символы в имени и ненулевых сопровождающих при отказе. Имя нормализуется через trim. UUID повтора регистронезависимый.

- 404 `INVITATION_UNAVAILABLE` для неизвестного slug, скрытой, истёкшей или удалённой публикации, в том числе при повторе. Когда публикация доступна, точный повтор возвращает исходную квитанцию даже после смены снимка.
- 409 `RSVP_FORM_CHANGED` при новой отправке устаревшей формы, `IDEMPOTENCY_KEY_REUSED` при изменении уже принятого запроса, `RSVP_LIMIT_REACHED` при достижении 300.
- 422 `VALIDATION_FAILED` для неверного ввода, 429 `RATE_LIMITED` с `Retry-After`, 503 при техническом сбое.

## Хранение и интеграция с E2-04

- `publications` — стабильная связь проект → slug, видимость и текущая граница срока. `publication_snapshots` сохраняет копию контента, номер ревизии и версию схемы анкеты. Для текущего снимка `superseded_at IS NULL`; БД допускает один такой снимок на публикацию. ID снимка служит `formVersionId`.
- `rsvp_responses` связан с конкретным снимком той же публикации. Уникальная пара `publicationId + keyHash` защищает от дубля, общий подсчёт по `publicationId` учитывает все снимки. При принятии ответа берётся блокировка строки проекта и затем перечитывается активность. E2-04 должен брать ту же блокировку при переключении версии и видимости. Квота и частотный лимит проверяются в транзакции записи.
- `rsvp_rate_limits` живёт отдельно от заявок. Для нескольких экземпляров задаётся общий `RSVP_RATE_SECRET` из минимум 32 случайных байт в hex. Локально возможен эфемерный ключ процесса. Production без корректного ключа возвращает 503 для новых ответов. Счётчик действует 15 минут, фоновая очистка удаляет истёкшие записи. Доверенный прокси для гостевого UI должен определить origin и схему передачи IP. Текущий сервер использует адрес соединения и игнорирует присланный клиентом `X-Forwarded-For`.
- Миграция `20261121070000_publication_rsvp` добавляет таблицы без данных. [Admin publish](e2-04-admin-publication.md) создаёт снимок и сразу открывает его для RSVP. UI и гостевой proxy добавляются отдельно. При удалении ответа понадобится политика хранения ключа Q-11.

## Воспроизведение проверок

Из корня проекта с локальной PostgreSQL выполните `npm run db:migrate:test`, `npm run build --workspace @povod/api`, затем `npm run test:database`. Шесть HTTP/PG тестов E3-01 проверяют контракт без сессии и приватных данных, валидацию, принятие и отказ, повторы, смену версии, недоступность, конкурентный лимит 300 и частотное окно. Они создают синтетические публикации только в test-БД. Ручная проверка гостевого UI появится с E3-01b.
