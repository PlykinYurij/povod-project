## Решение для начала

Рекомендация, ещё не выбор владельца: Docker Desktop с WSL2 для PostgreSQL; приложения и npm оставить в Windows/PowerShell. Следующие локальные сервисы смогут использовать тот же способ запуска без переноса приложений в Linux. Нужна установка и запуск системного runtime владельцем либо отдельное поручение на установку. Наличие `docker.exe` недостаточно: должна работать связь CLI с engine.

Альтернатива: установленный PostgreSQL, если владелец выбирает его и предоставляет доступ к выделенному локальному экземпляру. Пароли не передавать в чат и не коммитить. Адрес существующей БД не разрешает её очистку или изменение ролей.

## Объём после снятия блокера

- Зафиксировать поддерживаемую версию PostgreSQL после проверки официальной поддержки и совместимости будущей Prisma. Образ, digest и номер версии сейчас не выбраны.
- Создать отдельные локальные БД и роли dev/test. Ограничить сетевой доступ loopback; роли без superuser, создания ролей/БД. Проверить взаимный запрет подключения: разные имена не защищают от разрешения CONNECT через PUBLIC.
- Подготовить безопасный env-пример и инструкции получения локальных секретов вне Git. Не печатать connection strings с паролями и не перезаписывать пользовательские env.
- Добавить проверенные запуск, readiness, остановку и повторный запуск с сохранением данных. Документировать реальные команды после выполнения. Повторный старт не сбрасывает volume/БД; смена credentials существующего хранилища — отдельное действие.
- Проверить изоляцию на синтетических данных. Не включать разрушительную очистку или незащищённый reset. Будущий test-runner E1-06 отдельно проверяет test-маркер и роль перед очисткой.

Не входит: Prisma/миграции/seed продукта, HTTP readiness, регистрация, медиа, почта, CI PostgreSQL, серверы и деплой. Root `/health` остаётся liveness без зависимости от БД. Миграционный слой и интеграционные тесты — E1-06.
