# Допущения реализации MVP v2

21.11.2026. Владелец поручил продолжать задачи последовательно, фиксировать вопросы и выбирать разумные решения без остановки на каждом из них. Это рабочие решения ведущего, **не ответы владельца**. При изменении указываем затронутые задачи/миграции/проверки. Решения [D-42/43](decisions.md) имеют приоритет.

Непринятые коммерческие цены не заменяем выдуманным прайсом. Реальные платежи, привязка аккаунта, production DNS/почта и выпуск остаются отдельными операциями; публичный запуск без нужных данных не объявляется готовым.

A-06 (E2-01d): рабочая валюта RUB, цена — integer копейки, priceVersion. До утверждённых сумм seed price=null, публичный UI честно показывает «Цена уточняется»; это техническое промежуточное состояние, не изменение фиксированной цены в согласованном продукте и не обещание бесплатности. Синтетический прайс только в povod_test. К публичному приёму заказов/публикации Q-27 нужен; изменение реальной цены впоследствии должно увеличивать priceVersion атомарно, заявки фиксируют свою согласованную стоимость.

A-07 (V2-02): общая форма — contactName 1–80, нормализованный phone (+ и 7–15 цифр), channel TELEGRAM/MAX/VK и contactValue 1–200 как простой текст. Технический privacyConsent строго true и version/время сохраняются, утверждённый юридический текст/retention Q-10 отдельно. Rate 10/IP/15 минут и 3/phone/час; HMAC secret общий для экземпляров, без него новые production submissions 503, liveness/чужие auth сценарии не отключаются. Повтор UUID/body получает исходный receipt RECEIVED, не текущий operator status. Эти числа и формат — выбранные ведущим defaults, не ответы владельца.

Не вводили выдуманный профильный regex MAX/VK: [официальный Telegram FAQ](https://telegram.org/faq#usernames-and-t-me) описывает usernames/ссылки, [официальная справка MAX](https://help.max.ru/help) доступна, конкретный единый формат профиля для всех выбранных каналов этим проходом не подтверждён; VK FAQ был недоступен web-инструменту. Проверено 21.11.2026. Поэтому контакт — текст для оператора, без проверки существования/автоfetch/автоматического href.

A-08 (V2-01): одна открытая заявка на project, но draft редактируется. Intake допускает неполный сохраняемый draft; полная readiness только у admin publish. Цена сравнивается с отображённой expectedPriceVersion и фиксируется snapshot; последующая смена каталога не меняет quote. Null-прайс не free и не готов к публикации. Owner GET возвращает currentPrice отдельно от зафиксированной request.price, в том числе для скрытого поддерживаемого шаблона. История terminal заявок/пояснения отказа должны быть добавлены с operator status V2-03/05; текущий GET только открытой заявки не выдавать за историю.

A-09 (перед dev→production): проверить совместимость host-only cookies с Next SSR и единым артефактом. Предпочтительно браузерный API под тем же platform origin через reverse proxy, server-only trusted internal API origin; не запекать staging hostname в NEXT_PUBLIC при сборке переносимого артефакта. Сверить OS/arch native dependencies CI-артефакта с dev/prod. Сейчас это зафиксированная архитектурная задача выпуска, не уже настроенный proxy/runtime config; локальный API на том же 127.0.0.1 с другим портом работает.
