# E1-07 · Комплект сборки по SHA

**Review:** реализовано и проверено, ожидается приёмка владельцем. Коммит с кодом builder и первый опубликованный preview подтверждены в отчёте; production и dev-стенд не создавались.

Зависимость E1-02 принята в main. Источник: NFR-16, [план выпуска](../operations/release-plan.md), [backlog](backlog.md). Статус и фактические проверки — [отчёт](../qa/e1-07-report.md).

Результат одного PR: web/api runtime-архивы и manifest одного точного коммита с целевой ОС/архитектурой/Node, контрольными суммами и результатами проверок. Комплект из принятого main может стать кандидатом dev; ветки/PR/локальные сборки дают только preview. Сборка продукта для каждого приглашения не появляется: это сборка версии сервиса.

Входит: Next standalone, упаковка Nest dist с production-зависимостями, сборка из чистого git archive, unit-проверки целостности на Vitest, изолированный HTTP/static smoke готовых архивов, immutable upload в Actions и инструкция проверки доверенного digest. Общие scripts/config/lockfile ведёт один исполнитель.

Не входит: серверы/домены/деплой/БД/миграции/worker/почта/подпись и аттестация выпуска. Отсутствующие компоненты не добавляются в manifest фиктивно. Поставщик и реальные ресурсы Q-13 будут выбраны для E1-03.

Приёмка:

1. `npm test`, `npm run typecheck`, `npm run build` проходят; actionlint проверяет workflow.
2. Builder получает файлы только из точного committed snapshot, требует чистый checkout, не смешивает локальный .env и build outputs со сборкой коммита.
3. Manifest фиксирует SHA, run/attempt, Linux x64/Node 26.13.0 для CI, SHA-256 и размер каждого runtime-архива. Manifest digest записывается в доверенный CI summary, вне скачиваемого комплекта.
4. Готовые архивы распаковываются вне checkout. Web `/` + CSS и API `/health` отвечают 200 без исходников, npm install или повторной сборки на месте запуска.
5. Изменение архива, manifest, неверный SHA и неподтверждённые проверки приводят к отказу verifier. Preview не принимается как candidate без явного opt-in для локального осмотра.
6. Каждый run/attempt имеет отдельную identity; повторная запись того же комплекта запрещена. Upload artifact фиксирует ID/digest, не перезаписывает старую публикацию. Побайтовая воспроизводимость двух независимых build не обещается.
7. После успешных проверок изменения публикуются в ветке задачи, без merge/деплоя. Владелец принимает конкретный артефакт, а не только имя ветки.
