## Правила карточек и статусы

ID исходного §13 сохранены. Ранее широкие пункты сужены до одного результата PR; новые суффиксы/ID покрывают выделенную работу. E1-02 теперь только PR CI каркаса, его тестовая БД выделена в E1-06; E1-03 — закрытый dev, ручной prod отдельно E1-03b. E1-04 — регистрация, сессии/reset выделены; E2-02 — приватный draft API, UI отдельно. Это уточнение декомпозиции, не потеря исходных требований.

Начальный статус всех реализационных задач **Backlog**, кроме E1-01 **Blocked**. Документы E0 — **Review**, не Done: владелец ещё принимает оставшиеся решения. Зависимость означает готовый/принятый результат, а не просто наличие файла. Ready только после разрешения блокирующих вопросов, понятных данных/контракта/проверок и доступных входных инструментов. Таблицы ниже дают результат, роль, зависимости, требования и приёмку/метод для одного PR; исполнитель переносит строку в отдельную карточку, не объединяет этапы в один большой PR.

## Предложение GitHub Projects (только локально)

Поля: Task ID, статус, приоритет P0/P1/P2, этап, область web/api/docs/infra, роль/ответственный, зависимости ID, FR/NFR, Q-блокеры, ссылка PR, verification evidence, принятый SHA/release отдельно. Статусы: Backlog → Ready → In progress → Review → Verification → Done; Blocked отдельно с причиной и следующим действием. Done не означает production.

Начально: E0-01/02/03 — Review, E1-01 — Blocked (B-02), E1-00 — Backlog до разрешённого инструментального шага, остальные Backlog с зависимостями. Ни одной карточки в GitHub не создано. После снятия B-02 и принятия E1-00 переносим E1-01 в Ready; отсутствие бизнес-решений Q-04/16/19 его не блокирует.

Следующие две после каркаса: E1-02 (CI существующих проверок) и E1-05 (локальная PostgreSQL dev/test). Docker/WSL — блокер E1-05, не E1-01 или E1-02.
