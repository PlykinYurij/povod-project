# E2-01b · Часть 1: read-only каталог

Актуальный сценарий описан в [части 2](e2-01b-draft-creation.md). Для каталога с категориями и ценами требуется API с PostgreSQL. Ниже сохранена история read-only реализации.

**Read-only часть принята владельцем и интегрирована в main f9882f3 (PR #23)**, содержит 317799a. Ниже история выполнения. Полный выбор с созданием проекта ещё не выполнен.

## Результат

Публичный GET `/api/v1/templates?locale=ru|en` возвращает только реализованные версии шаблонов: сейчас wedding-garden-v1, заголовок, eventType, schemaVersion, две палитры, обязательность/порядок блоков, относительные demo/preview-image пути. Нужны только code-owned данные, без БД, сессии, cookies или прав владельца. Default locale RU; неверная/повторная locale и неизвестные query-поля → 422. API no-store, без Set-Cookie. POST не реализован.

OpenAPI 0.7.0 — источник типов/методов/hooks Orval в shared/api. Frontend не копирует DTO; дополнительно проверяет форму ответа, безопасные локальные ссылки и повторяющиеся ключи в runtime. Только каталог добавлен в allowlist transport; серверные account credentials не передаются. Неизвестные API-пути/параметры и мутации каталога не разрешены.

Страница `/templates` — Server Component, через plain generated method загружает API с locale сервиса, без Query/Mantine/providers кабинета. Главная → каталог → демо → каталог. Состояния loading/empty/error различаются; retry делает полную загрузку страницы. На API-запрос действует технический timeout 5 секунд, без автоматических повторов. Ошибки/внутренняя диагностика не выдаются за пустой каталог и не попадают в UI. Весь интерфейс RU/EN, контент демо и его локаль не меняются от языка каталога.

Четыре шаблона остаются границей MVP, но несуществующие три не выдаются за готовые карточки. Создания draft, выбора templateVersion для сохранённого проекта, БД, миграций, editor/upload/publish и RSVP в этом PR нет. Изменённый пользователем текст по D-36 и загрузка собственного фото остаются следующими зависимыми частями.

## Приёмка одного PR

1. Анонимный HTTP GET без DATABASE_URL → корректные локализованные метаданные; без user/project/private media полей и Set-Cookie. Query в runtime проверяется.
2. Swagger и Orval воспроизводимы; типы страницы — из generated contract. Не добавлены зависимости/инфраструктура/настройки внешних сервисов.
3. Loading, пустой каталог, ошибочный/некорректный ответ и успешный результат различаются. Ошибка не раскрывает SQL/внутреннюю диагностику, retry повторяет чтение.
4. На 360/1280 px нет горизонтального скролла; клавиатура доходит до основного demo-link. Никакая кнопка не выдаёт просмотр за создание/публикацию.
5. Cookies/Authorization/CSRF не попадают в публичный запрос; остальные transport guards сохранены.
6. Unit/component тесты рядом с модулями, настоящий HTTP-контракт и существующие DB/auth проверки проходят; types/build/format и browser-путь подтверждены в [QA](../qa/e2-01b-catalog-report.md).

## Локальная приёмка

Из корня в двух терминалах: `npm run dev:api:database`, `npm run dev:web`. Открыть `http://127.0.0.1:3000/templates` или ссылку на главной. Для одного каталога БД не обязательна: вместо helper допустим `npm run dev:api`, но login в этом процессе без DB не проверяется. API — `http://127.0.0.1:3001/api/v1/templates?locale=en`, Swagger — `/api/docs`.

Перейти в демо, вернуться, проверить RU/EN через сохранённую локаль сервиса, уменьшить окно до 360 px. Проверить ошибку API можно остановкой своего API в его терминале, затем нажать retry после запуска. Пустой каталог и повреждённый ответ проверяются fixtures; настоящая текущая registry содержит один шаблон и не имеет публичного управления.

Проверки из корня: `npm test`, `npm run typecheck`, `npm run build`, `npm run test:database` (после build и при готовой test-БД), `npm run format:web`, `npm run api:openapi`, `npm run api:generate`. Коммит/push не означают принятие или merge.
