# E2-04b · Публикация в админке и гостевая страница

[Контракт публикации](e2-04-admin-publication.md) · [FR-13/14](../povod-mvp-spec-v0.1.md) · [Правила адресов](../architecture/publication-addresses.md) · [Гостевой макет](../design/first-flow.md).

## Сценарий

1. В `/admin/projects` открыть заявку с подготовленным проектом и зафиксированной ценой. Проверить сохранённую ревизию и предпросмотр.
2. Ввести имя поддомена и подтвердить проверку приглашения и цены. При занятом адресе сервер возвращает ошибку под полем. При конфликте ревизии нужно обновить заявку и снова сверить предпросмотр. После технического сбоя неизменённая попытка повторяется с прежним UUID.
3. После принятия запроса админка показывает ссылку из серверной квитанции. Она доступна и после открытия карточки заново. Если браузер запрещает автоматическое копирование, адрес можно выделить и скопировать из поля.
4. При открытии гостевого адреса Next.js показывает исходный снимок «Тихого сада», подготовленное фото и метаданные для ссылки. Скрытая, удалённая, отсутствующая или истёкшая публикация даёт нейтральный 404. На гостевом хосте маршруты кабинета закрыты.

## API и границы

- OpenAPI 0.21.0 добавляет GET `/api/v1/public/invitations/by-address/{slug}`, который отдаёт только версию шаблона, ID снимка, контент и размеры обложки. `/cover/{snapshotId}` на гостевом хосте читает WebP соответствующего актуального снимка. Сервер проверяет срок и видимость и для страницы, и для фото.
- Для HTML, метаданных и фото применяется `no-store`, для гостевой страницы также `noindex`. ID фотографии, ключи хранилища, название проекта, контакты, сессия и роли остаются за границей публичного ответа. Кабинет и гость используют один web-сервис с разными поверхностями.
- Роль, версия заявки и состояние БД проверяются в NestJS при публикации. Next Proxy классифицирует входящий `Host` и не использует клиентский `X-Forwarded-Host`. Генерация title/description/Open Graph использует снимок в рамках того же SSR-запроса. [Next.js Proxy](https://nextjs.org/docs/app/api-reference/file-conventions/proxy) · [Next.js Metadata](https://nextjs.org/docs/app/getting-started/metadata-and-og-images).
- UI анкеты RSVP — E3-01b. Публичный выпуск также требует свой домен, wildcard DNS/TLS и проверку маршрутизации на реальном ingress. Локальная проверка использует вымышленные адрес и цену.

## Локальный запуск

Из корня проекта выполните `npm run db:migrate:dev`. В одном терминале запустите API, в другом web. Значение базового домена должно совпадать у обоих процессов.

```powershell
$env:PUBLIC_INVITATION_BASE_DOMAIN = 'invitations.example.test'
npm run dev:api:database
```

```powershell
$env:PUBLIC_INVITATION_BASE_DOMAIN = 'invitations.example.test'
$env:POVOD_INTERNAL_API_ORIGIN = 'http://127.0.0.1:3001'
npm run dev:web
```

При наличии локального администратора и заявки с тестовой ценой опубликуйте её из админки. Проверьте HTML без правок DNS. Замените `garden-demo` на введённое имя.

```powershell
curl.exe -i -H 'Host: garden-demo.invitations.example.test' http://127.0.0.1:3000/
```

Локальная команда `npm run test:database` прошла 247 проверок на test-БД по HTTP. `npm test` прошёл 179 проверок, включая подтверждение, сохранение ключа повтора и отказ при занятом slug. Chrome-проверка запускалась на локальной production-сборке Next, тестовой БД и локальной имитации S3. Покрыты публикация в админке, повторное открытие квитанции, отказ clipboard, гостевые HTML/OG и WebP, ширина 360 px, поддельный forwarded host, изоляция кабинета, нейтральный ответ и закрытая обложка после истечения. Доступность реального DNS, TLS и стороннего S3 не проверялась.
