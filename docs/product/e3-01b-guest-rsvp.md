# E3-01b · Ответ гостя на приглашение

Гость открывает опубликованный «Тихий сад» без аккаунта. Анкета принимает имя или псевдоним, факт участия и до двух сопровождающих. При отказе поле сопровождающих скрыто и отправляется 0. Лимит в 300 остаётся общим для проекта. Поля анкеты v1 и рабочее частотное окно сохраняются по допущениям Q-04/11. [Исходные FR-15/16](../povod-mvp-spec-v0.1.md) · [Контракт E3-01](e3-01-rsvp-next.md) · [Вопросы](open-questions.md).

## Поведение гостевой страницы

| Ситуация | Результат |
| --- | --- |
| Отправка | Одна попытка в полёте. Подтверждение появляется после квитанции API |
| Технический сбой с неизвестным результатом | Ввод остаётся на экране, кнопка повторяет прежние данные с тем же UUID |
| Протухшая версия | Нужно обновить приглашение и посмотреть актуальную форму. Автоматической отправки нет |
| 429 с Retry-After | Таймер сохраняет форму и указывает, когда можно повторить |
| 300 ответов или приглашение стало недоступно | Показано одно из двух сообщений, дальнейшая отправка закрыта |
| 422 | Ошибки полей отображаются рядом с вводом |

Версия анкеты приходит в объекте `rsvp` вместе с публичным снимком. Браузер отправляет через `POST /rsvp` на том же хосте. Next проверяет Origin и допустимый host, ограничивает тело 4 КиБ и пересылает JSON только на точно заданный внутренний API. Куки кабинета и Authorization браузера не пересылаются. [Гостевая E2-04b](e2-04b-guest-page.md).

## Локальная проверка

Запустите API и web по [инструкции гостевой страницы](e2-04b-guest-page.md#локальный-запуск). Перед запуском web дополнительно установите в его PowerShell `$env:POVOD_RSVP_LOCAL_HTTP = '1'`. Режим допускает HTTP для гостевого домена `.test` и внутренний API только на loopback. Для проверки браузером направьте тестовый гостевой host на локальный Next, например локальным правилом разрешения имён изоляционного браузера. Проверка требует опубликованный тестовый проект и синтетические данные.

Заполните анкету сначала с участием, а затем на свежей вкладке проверьте отказ. Для технического повтора потеряйте ответ после commit и нажмите «Повторить отправку». Совпадут UUID и обе квитанции, а в PostgreSQL останется одна запись на попытку. Интеграционные проверки лимита и срока используют `npm run test:database` после сборки API. Миграций в этой карточке нет.

23.11.2026 локально прошли 187 тестов Vitest и 248 проверок HTTP/PostgreSQL. В Chrome на ширине 360 px проверены запись, потерянный после commit ответ с повтором 201 → 200, отказ без сопровождающих и истечение публикации между показом формы и отправкой. Интеграционные тесты проверили разные счётчики IP при валидном relay и отказ без него.

## Условия для HTTPS через ingress

- Ingress должен перезаписывать `X-Povod-Rsvp-Client-IP` проверенным IP на каждом запросе. Доступ к портам Next и Nest снаружи должен проходить через доверенный ingress и заданные маршруты. `X-Forwarded-For` из браузера не участвует в расчёте квоты.
- `RSVP_RELAY_SECRET` — 32 случайных байта в lowercase hex. Настраивается одинаково в Next и Nest как секрет окружения, отдельно от `RSVP_RATE_SECRET`. Next заменяет заголовок доказательства собственным. Nest в production принимает POST только от настроенного relay.
- Перед выпуском проверить с реальным ingress, что две клиентские сети получают отдельные лимиты, подставленный публичным клиентом заголовок перезаписывается, а REST-маршрут Nest не открывает обход. DNS, TLS, ingress и легальные условия хранения Q-10 остаются в проверке выпуска.
