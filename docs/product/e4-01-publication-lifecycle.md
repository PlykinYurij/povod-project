# E4-01 · Жизненный цикл публикации

Основа — [FR-12 и FR-20](../povod-mvp-spec-v0.1.md), [D-05–07, D-11, D-38 и D-41–43](decisions.md) и [A-03](implementation-assumptions.md). Публикацией управляет администратор. Уже опубликованный проект доступен владельцу только для чтения. Временное снятие открывает редактор, истечение срока закрывает редактор. Шаблон существующего проекта и публичный адрес сохраняются.

## Первая поставка E4-01 · Снятие и редактор

`POST /api/v1/admin/projects/{id}/unpublish`, OpenAPI operationId `unpublishAdminProject`. Требуются сессия администратора, JSON, проверка источника, CSRF и UUID в `Idempotency-Key`. Тело содержит `expectedProjectRevision`, `expectedPublicationVersion`, явный `mode` и обязательную `reason` длиной 1–240 символов после обрезки пробелов. Причина предназначена для аудита и не должна содержать личные данные.

| Режим | Доступ | Остаток |
| --- | --- | --- |
| `PAUSE_PERIOD` | `PAUSED`, гостевая страница и новые RSVP недоступны | Остаток фиксируется на момент снятия. Место в квоте занято |
| `KEEP_RUNNING` | `UNPUBLISHED`, гостевая страница и новые RSVP недоступны | Дедлайн сохраняется. Место освобождается в момент истечения |

Успешный ответ 200 содержит `publicationId`, `publicationVersion`, `status`, `expiresAt` и `remainingMs`. В паузе отсчёт даётся через `remainingMs`, а `expiresAt` равен null. При продолжающемся сроке возвращается `expiresAt`, а `remainingMs` равен null. Повтор исходного запроса возвращает сохранённую квитанцию без нового эффекта. Тот же ключ с изменённым телом, устаревшая версия, истечение и конфликт состояния дают 409. Проект, которого нет или который удалён, даёт 404. Причина, актор, время и режим сохраняются в аудите. Гость получает прежнее нейтральное состояние недоступности.

Состояние для интерфейса приходит из `publicationLifecycle` оператора, отдельно от исторической квитанции первичной публикации. Снятие сохраняет снимок, ответы и адрес. Возобновившееся редактирование меняет черновик и увеличивает его ревизию. Снятие и приём RSVP используют общую блокировку проекта. Активные и приостановленные проекты продолжают занимать места и сохраняют доступ к уже принятым ответам по действующим правам.

### Приёмка

- Администратор может снять опубликованный проект в обоих режимах. Владелец и гость не могут вызвать операцию.
- После снятия закрыты гостевая выдача и приём RSVP. Принятые ответы, прежний снимок и публичный адрес сохранены.
- Повтор с тем же ключом и телом возвращает квитанцию. Конкурирующая операция или устаревшая ревизия не применяет второй переход.
- В активном состоянии изменения формы и фото запрещены. После снятия открыты для прежних владельцев прав, при истечении снова закрыты. Правила проверяются на сервере.
- Для продолжающегося срока проверена граница истечения. На паузе сохраняются остаток, ответы и место в квоте, даже когда изначальный дедлайн уже в прошлом.

Проверки — `npm run test:database` на изолированной PostgreSQL, `npm run typecheck`, `npm run build` и воспроизводимый OpenAPI/Orval после изменения HTTP-контракта.

## Следующие поставки

Следующая серверная часть E4-01 возвращает приглашение по тому же адресу только по команде администратора после предпросмотра конкретной ревизии. Возобновление сохраняет отвечавших гостей, явно публикует новый снимок и продолжает существующий период. Открытые правила нового заказа и расчёта цены учитываются отдельно от возобновления оставшегося периода.
