# E1-04c · Backend восстановления по email-коду

Актуализация 19.11.2026: backend присутствует в main d19e115; web реализован и проверен на Review в feat/web-sign-in — [карточка](e1-04-identity-web.md), [QA](../qa/e1-04-identity-web-report.md). Ниже сохранены границы backend-карточки и её исторические доказательства.

Backend-карточка от main `0a4fa0b`: FR-04/NFR-07/09, [D-31](decisions.md), [identity](../architecture/authentication.md). Её результат — backend и локальная тестовая почта; web-доказательства вынесены в продолжение выше. Production SMTP/очередь и выпуск отдельно.

Контракт `/api/v1/auth/password-reset` (JSON, Origin, CSRF, no-store):

- POST `/request`: `{email}` → одинаковый 202 `{message}` для существующего/неизвестного email; resend — тот же маршрут. Три запроса/email/час, десять/IP/15 минут, включая неизвестные email; 429 с Retry-After.
- POST `/confirm`: `{email,code,newPassword}` → 204; неверный/истёкший/использованный код — одинаковый 400 RESET_CODE_INVALID. Code — строка из шести цифр, включая ведущие нули. NewPassword по D-28. Код живёт 10 минут; пятая неверная попытка исчерпывает код. Повторная отправка отменяет старый.
- Успех атомарно меняет hash, потребляет код, отзывает все Session под тем же User lock, что login. Новая Session не создаётся. После потери успешного ответа — обычный вход с новым паролем; повтор confirm не меняет пароль ещё раз.
- Прочие ответы: 403 CSRF/Origin, 415 content type, 422 DTO/unknown fields, 400 malformed JSON, 413 body limit, 503 зависимости. Технический контекст CSRF не означает вход.

Решение локальной доставки: изолированный файловый перехватчик, явно включаемый только вне production; письма не отправляются в сеть и не возвращаются в HTTP/Swagger/логи. Путь не зависит от email. Реальный SMTP/очередь отдельно; production-reset без настроенного транспорта закрыт 503. Новые библиотеки не требуются.

Проверки: реальный HTTP/PostgreSQL/test inbox — одинаковый ответ неизвестного адреса, валидный reset, два браузера/отзыв всех Session, старый/новый пароль, неверные/истёкшие/повторные коды, пять попыток, resend, concurrent confirm/request, rate limits email/IP/гонка, CSRF/DTO/ошибки БД и inbox. Отдельно Swagger/snapshot, typecheck/build, существующие suites и isolated artifact smoke. Тесты используют только синтетические адреса и отдельную test-БД; код не печатать в отчёте.
