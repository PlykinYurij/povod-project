# Критерии приёмки · MVP v2

Источник: [неизменяемое ТЗ FR-01–25/NFR-01–16](../povod-mvp-spec-v0.1.md), [D-38/39](decisions.md), [MVP v2](mvp-v2.md). Это план проверок, не отчёт готовой новой реализации. Успешные старые identity/draft тесты не доказывают admin/requests/publish.

## Прежние FR с новым маршрутом публикации

| FR | Данные / действие → ожидаемый результат | Проверка / открытое |
| --- | --- | --- |
| FR-01 | Открыть категорию → карточки с названием/фиксированной ценой и демо; отсутствующие шаблоны не выданы за готовые | UI/API; стартовые четыре остаются целевым объёмом, сейчас один renderer |
| FR-02 | Начать регистрацию → до email-кода нет User/Session; подтвердить → аккаунт/сессия | Существующие HTTP/PG + web регрессии D-30/32 |
| FR-03 | Войти/выйти → session/redirect/cache соответствуют реальному входу | Регрессии; обычный вход без нового кода |
| FR-04 | Reset-код + новый пароль → одноразовость и отзыв сессий | D-31/34, HTTP/PG |
| FR-05 | Клиент создаёт проект из версии шаблона → только его приватный draft; повтор key не дублирует | E2-02, пять draft; admin-assisted новый R2-06 |
| FR-06 | Заполнить конкретную форму/optional-блок → типы/границы/порядок соблюдены, данные сохранены | D-36/37; выбор SQL/JSONB Q-23 не отменяет типизацию |
| FR-07 | Выбрать разрешённую палитру/блок → renderer показывает допустимый вариант | UI + runtime validation |
| FR-08 | Две вкладки сохраняют одну revision → один успех, один conflict | HTTP/PG, локальный ввод не теряется |
| FR-09 | Открыть свою/чужую сохранённую revision → свой preview, чужой нейтральный 404 | Private preview, нет публичного RSVP side effect |
| FR-10 | Валидное/невалидное фото → проверенный processing/ready/failed, нет чужого asset | Медиа ещё отдельная задача; 10/15МБ/40Мп |
| FR-11 | Клиент отправляет заявку, затем admin публикует согласованный проект → только второе действие даёт публичный URL | Изменено D-38; R2-03/05/07/09 |
| FR-12 | Изменить опубликованное → только разрешённые правилами исправления, live snapshot не меняется от draft save | Прежние D-17/36 не расширены; новый lifecycle Q-29 |
| FR-13 | Гость открывает активную ссылку → одобренные данные без контактов заявки/owner/private draft | SSR/runtime; admin-created и client-created одинаково безопасны |
| FR-14 | После admin commit показать URL → ссылка рабочая; заявка ещё без публикации не показывает ложный URL | Безопасный адрес и честный clipboard status |
| FR-15 | Гость заполняет небольшую анкету → валидное значение соответствует formVersion | Q-04; форма заказа отдельно |
| FR-16 | Повтор и гонка 300-го RSVP → без дубля/переполнения, недоступная публикация не принимает ответ | HTTP/PG; TTL гарантий Q-11 |
| FR-17 | Клиент читает ответы своего опубликованного проекта → чужие недоступны | Guest-assisted доступ Q-25 |
| FR-18 | Экспортировать XLSX → корректные данные без formula injection | CSV Q-17; доступ после expiry Q-19 |
| FR-19 | Подтвердить удаление неверного ответа → остальные целы, квота освобождена, replay не воскрешает | HTTP/PG; Q-11 |
| FR-20 | Проверить срок/паузу/недоступность → server enforcement без зависимости от cron | Исходно 90 дней D-19; изменения Q-26/29, не срок из референса |
| FR-21 | Удаление проекта → доступ отозван, нужные объекты очищаются по политике | Q-06/09/19; заявки/контакты отдельный объект |
| FR-22 | Удаление аккаунта → права отозваны, политика по заказам/бэкапам соблюдена | Q-10/25, не массовое удаление соседних клиентов |
| FR-23 | Отправить feedback → отдельное обращение, не автоматически оплаченный заказ | Не подменяет ServiceRequest |
| FR-24 | Клиент/admin вызывают operator routes → 403 клиенту, разрешённые действия admin с аудитом | Новый основной MVP путь, R2-05–07 |
| FR-25 | RU/EN сервис/кабинет/admin → переведены подписи/ошибки/состояния, авторский текст не переводится | D-36, ручные mobile/theme проверки |

## Новые требования R2

| ID | Исходные данные / действие | Ожидаемый результат / метод |
| --- | --- | --- |
| R2-01 Категории и цена | Два шаблона в разных категориях, изменить фильтр | Только подходящие карточки, фиксированная цена; API+UI; суммы Q-27 |
| R2-02 Типизированная версия | Подать неизвестные поля/неверный тип/не ту версию | 422 с paths, без сохранения; compile-time ошибки проверяет typecheck, runtime — интеграция |
| R2-03 Заявка с проектом | A отправляет свою revision/контакты; B подставляет projectId A | A получает подтверждение заявки, B 404; ни один не публикует; HTTP/PG |
| R2-04 Общая заявка | projectId отсутствует, контакты заполнены | Заявка без фиктивного проекта/User; необходимость входа Q-24; HTTP/PG+UI |
| R2-05 Admin очередь | Два обычных клиента и admin читают заявки/контакты | Только разрешённая выдача, нет публичной утечки/эскалации роли; HTTP и browser |
| R2-06 Подготовка оператором | Admin создаёт проект из общей заявки, повторяет запрос | Один проект/связь, конкретная форма/preview, правильный creator/customer по Q-25; HTTP/PG |
| R2-07 Admin publish | Клиент и два admin конкурируют за публикацию/один адрес | Клиент запрещён; одна атомарная публикация, no duplicate/ложного fulfilled, snapshot/адрес/audit согласованы; HTTP/PG |
| R2-08 Цена заявки | Каталоговая цена изменена после открытия/отправки | Нет молчаливой подмены условий, выбранная политика Q-27; HTTP+UI |
| R2-09 Согласованные данные | Client/admin изменили draft после просмотра другой стороной | Не публикуется незамеченная revision; конфликт/пересмотр по Q-28; HTTP/PG+UI |
| R2-10 Контакты и RSVP | Гость читает HTML/данные/отправляет ответ | Контакты заказчика не выдаются, RSVP не создаёт заявку на заказ; HTTP/SSR |
| R2-11 Оформление | Оригинальный шаблон с анимацией, mobile/reduced-motion/keyboard | Читаемость/доступность, RSVP работает без тяжёлых эффектов; browser/performance, не только unit |
| R2-12 Переход | Старый User/Session/Project/Garden payload и новая миграция | Не потеряны данные/ревизии/14 copy/null, нет автоматического admin; миграционный test/сверка |

## NFR

NFR-01/02: мобильность/браузеры нового редактора, admin и приглашений. NFR-03–05: сохраняются пороги исходника; профиль замеров дополняется анимациями и operator API, Q-12. NFR-06: keyboard/focus/inline errors/reduced-motion. NFR-07–10: owner+admin authorization, CSRF, безопасные контакты/URL/uploads, атомарные jobs/idempotency. NFR-11/12: согласованные сроки новых контактных данных и restore без возврата удалённого, Q-10/19. NFR-13/14: запуск/наблюдаемость/проверки. NFR-15/16: раздельные среды и один артефакт по SHA с ручным production release владельцем. Новых успешных NFR-прогонов этим документом не заявлено.
