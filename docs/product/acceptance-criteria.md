# Критерии приёмки

Источник: [FR-01–25, §6](../povod-mvp-spec-v0.1.md#6-функциональные-требования-и-критерии-приёмки), [NFR-01–16, §7](../povod-mvp-spec-v0.1.md#7-нефункциональные-требования). Статусы: [README](README.md). Уточнения владельца: [decisions.md](decisions.md), приоритетнее исходного ТЗ. Это будущая приёмка, не отчёт выполненных тестов: приложения ещё нет.

Для каждого прогона фиксировать версию, предусловия/данные, действие, фактический результат и свидетельство. Предложения Г и открытые ветки Q из [реестра](open-questions.md) проверять после решения владельца. Ниже — аналитическая основа, не финальный тест-план.

## Функциональное поведение

| ID источника | Условие и действие → наблюдаемый результат | Проверка / открытые условия |
| --- | --- | --- |
| FR-01 | Без аккаунта открыть каталог → четыре шаблона и демо; отправка демо не создаёт настоящую анкету | Интерфейс и отсутствие сохранённого RSVP |
| FR-02 | Зарегистрироваться/войти → после авторизации черновик и публикация не требуют подтверждения email (D-02, замена исходного условия FR-02) | UI/API: нет отдельного барьера подтверждения у авторизованного пользователя; регистрацию и первичный вход детализировать в проектировании |
| FR-03 | Войти/выйти → сессия отозвана; неверный пароль и несуществующий email не различаются сообщением | Cookie, API, повтор запроса после выхода |
| FR-04 | Reset существующего/несуществующего email → нейтральный ответ; смена пароля → ссылка повторно не работает, старые сессии отозваны | Два клиента и перехватчик писем; TTL — Q-11 |
| FR-05 | Создать проект после входа → приватный черновик; без авторизации создание запрещено; черновик из выбранного шаблона; превышение квоты отклонено сервером | Два аккаунта/конкурентные запросы; число черновиков — Q-08 |
| FR-06 | Изменить поля и выключить разрешённый блок → результат сохранён и виден в предпросмотре, порядок фиксирован | Повторное открытие; обязательные поля/блоки — Q-03 |
| FR-07 | Выбрать готовую палитру → тема меняется; произвольные код/стили не принимаются | UI и попытка обхода запросом |
| FR-08 | Оборвать сеть, отправить старую ревизию → видны ожидание/ошибка, ложного успеха нет, новая версия не затёрта | Две вкладки и управляемая сеть |
| FR-09 | Открыть предпросмотр владельцем в двух ширинах → общий рендерер/валидация; другой аккаунт/гость не получает доступ | Сравнение с публикацией, негативный доступ |
| FR-10 | Загрузить разрешённые и поддельные/слишком большие изображения → сервер принимает допустимые, исправляет поворот, удаляет метаданные, создаёт размеры/WebP | Набор файлов/анализ производных; числа — Q-08 |
| FR-11 | Публикация авторизованным владельцем → поля, тариф, фото и квоты проверены; дополнительного подтверждения нет. Повтор/конкуренция не дают дубликат, лишний период или третий активный проект | D-02; API/состояние; период — D-05/07, квота паузы — Q-01 |
| FR-12 | После первой публикации изменения контента/структуры/анкеты и смена шаблона запрещены; снятие с публикации не снимает ограничение (D-09/10) | UI и прямые запросы; возможное исключение текстовых исправлений Q-16 пока не проверяется как реализуемое |
| FR-13 | Открыть на телефоне/десктопе → только опубликованные данные, корректные title/description/OG, noindex | HTML/UI; эталон — Q-03/12 |
| FR-14 | Скопировать ссылку → подтверждение только после успеха; отказ clipboard не показан как успех; URL без email | Clipboard и URL |
| FR-15 | Отправить допустимую/невалидную анкету → допустимая сохранена с верной версией, неверные типы/длины/значения отклонены | API/UI; при отказе сопровождающих ноль (D-04); форма неизменна после публикации — D-10 |
| FR-16 | Повтор одного запроса → одна запись; одинаковые имена в разных запросах допустимы; конкуренция не превышает 300 записей; истечение/блокировка запрещают новые | Параллельные запросы/время; rate limits — Q-11 |
| FR-17 | Владелец фильтрует → список/счётчики соответствуют данным; B не видит ответы A | Контрольный набор; счётчик людей — Q-04 |
| FR-18 | XLSX владельца содержит сохранённые ответы, корректны кириллица/переносы/значения; пользовательский ввод остаётся текстом, а не исполняемой формулой; чужой экспорт запрещён | Открытие в табличном редакторе и проверка прав; XLSX по D-12, судьба CSV — Q-17 |
| FR-19 | Подтвердить удаление → удалена только выбранная запись, квота освобождена, другие ответы не изменены; отмена не удаляет | Список/квота/повтор |
| FR-20 | Снятие владельцем или admin с паузой → остаток заморожен, контент/ответы сохранены до возобновления. Admin без паузы → доступ закрыт, срок продолжает идти. Возобновление не выдаёт новый полный период | Управляемое время для каждого режима; очистка не удаляет данные во время паузы. Квоты/даты после паузы — Q-01, переходы admin — Q-05 |
| FR-21 | Удаление → публичная выдача и RSVP прекращаются, обычная публикация проект не восстанавливает, очистка по политике | Время отзыва HTML — Q-06, очистка — Q-10; критерий условный до решений |
| FR-22 | Запрос удаления аккаунта → сессии/публикации отозваны, данные/копии очищены по политике | Сквозная процедура с восстановлением копии; Q-10 |
| FR-23 | Тема/email/текст доставлены superadmin; вложения/невалидные данные отклонены, частота ограничена | UI/API; точные пределы — Q-11 |
| FR-24 | Admin снимает с паузой/без неё, действие с причиной аудируется; владелец читает/экспортирует и сам возобновляет (D-08). Неавторизованный доступ запрещён | Оба режима срока, доступ к чужому проекту, сохранение запрета правок после публикации |
| FR-25 | Переключить язык и вернуться → локаль сохранена; сервис/кабинет RU/EN, приглашение/анкета RU | Матрица экранов и ошибок; расширение публичного RU/EN — Т |

## Качество и эксплуатация

| ID источника | Проверяемый результат | Метод / открытые условия |
| --- | --- | --- |
| NFR-01 | От 360 px нет горизонтального скролла контента, формы/редактор доступны | Матрица ширин и действий |
| NFR-02 | Актуальная и предыдущая основные версии Chrome/Edge/Firefox/Safari; отдельно iOS Safari/Android Chrome | Зафиксировать версии на дату пилота и пройти основные потоки |
| NFR-03 | LCP ≤ 2,5 с, CLS ≤ 0,1 на фиксированном mobile/4G | Эталон устройства/сети/контента/кеша и прогоны — Q-12 |
| NFR-04 | Начальная загрузка типового приглашения ≤ 2 МБ, нижние фото отложены, размеры заданы | Сетевой отчёт; граница загрузки/эталон — Q-12 |
| NFR-05 | 1 000 проектов, 20 запросов/с, 10 минут: p95 ≤ 500 мс, ошибок < 1%; без почты/обработки фото/искусственно неверных запросов | Смесь запросов и среда — Q-12; сохранить отчёт |
| NFR-06 | Клавиатура, видимый фокус, подписи/ошибки, контраст, reduced-motion; ключевые экраны проверены по WCAG 2.2 AA | Ручные/автоматические проверки; перечень экранов — Q-12, не заявление о сертификации |
| NFR-07 | Изоляция A/B, HttpOnly/Secure cookie, CSRF-защита, хеши паролей, лимиты входа/писем | Негативные API/браузерные проверки; параметры — Q-11 |
| NFR-08 | Текст не исполняется, запрещённые URL/HTML/SVG/анимация отклоняются | Набор вредоносного контента; конкретный перечень уточнить при проектировании |
| NFR-09 | Квоты/параллелизм фото/писем/проектов/RSVP не обходятся конкуренцией, бюджетные уведомления работают | Границы, сбои worker, тест уведомления; Q-08/11/13 |
| NFR-10 | Сбой публикации сохраняет рабочую версию, повтор фонового задания не дублирует результат | Инъекция сбоя и повторы |
| NFR-11 | Бэкап БД ежедневно, минимум 7 точек, срок до 30 дней; пробное восстановление: RPO ≤ 24 ч, RTO ≤ 4 ч | Отчёт с временем потери/восстановления; точная ротация/удалённые данные — Q-10 |
| NFR-12 | Требующие восстановления медиа восстановлены из отдельного места/версий; репликация не подменяет бэкап | Пробное восстановление и сверка со снимками |
| NFR-13 | Health/readiness корректны, сбои/диск вызывают алерты, request_id связывает события, секретов/анкет в логах нет | Контролируемые отказы и синтетические логи |
| NFR-14 | Чистое окружение воспроизводит запуск/миграции/seed/CI по документации и lockfile | Позже, после появления инструментов |
| NFR-15 | Dev не читает prod БД/медиа/секреты, тестовые письма не уходят реальным получателям | Негативный доступ и почтовый маршрут |
| NFR-16 | Production получает те же проверенные SHA/digest, выпуск сериализован и вручную запускается владельцем | Проверенный/непроверенный SHA и конкуренция выпусков; без выпуска сейчас |

Допуск к пилоту: матрица §14, принятые исключения, закрытые критичные дефекты, проверенное восстановление, правовые условия §8 и принятие точного SHA владельцем на dev. Локальная сборка этого не заменяет.

## Дополнительные граничные сценарии ревью 10 ноября

| Источник | Сценарий → ожидаемый результат / условие |
| --- | --- |
| FR-08, NFR-07 | Истечение сессии во время сохранения → явная ошибка, нет ложного «сохранено»; после входа проверяется фактическая ревизия |
| FR-10/11, NFR-10 | Передача фото завершилась, обработка упала → фото не готово к публикации; ошибка видна, активный снимок не повреждён. Числовые границы файлов проверяются только после Q-08 |
| FR-11/12 | Правка одновременно с публикацией → опубликован один целостный валидированный снимок; выбранная ревизия/обработка конфликта должна быть описана до реализации |
| FR-11/20 | Два занятых места, одно из них на паузе → публикация третьего запрещена и при конкурентных запросах (D-11); возобновление не создаёт новое право |
| FR-13/15/16/20 | Открытие/отправка при паузе, истечении, обоих admin-режимах или удалении → нет нового ответа и утечки закрытого контента; несуществующая ссылка также не показывает данные |
| FR-16 | Ответ сохранён, подтверждение потерялось → повтор не создаёт дубликат. Повтор после закрытия сайта/удаления записи требует Q-11, не считать возвращаемый статус заранее определённым |
| FR-17–19 | Пустой список/пустой фильтр/ошибка получения различимы; удаление последнего ответа даёт пустое состояние и освобождает квоту. Пустой экспорт и повтор удаления уточнить при проектировании функции |
| FR-20, D-05–07 | Несколько циклов паузы/возобновления расходуют только интервалы расхода; admin без паузы расходует время даже без публичной выдачи. Остаток не растёт от повторов |
| FR-20–22, D-12 | Пауза/возобновление, истечение периода и наступление даты события не удаляют принятые ответы. Явное удаление ошибочного ответа/проекта/аккаунта проверяется отдельно |
| FR-24 | Admin снимает с паузой/без неё, действие с причиной аудируется; владелец читает/экспортирует и сам возобновляет (D-08). Неавторизованный доступ запрещён | Оба режима срока, доступ к чужому проекту, сохранение запрета правок после публикации |

Численные пороги NFR не изменены. Их воспроизводимость пока зависит от Q-12; заявления «быстро», «безопасно» или «актуальные браузеры» не заменяют протокол и зафиксированную матрицу версий.

Дополнение D-13 (FR-06/11/20): прошедшая дата не блокирует публикацию, наступление даты события не меняет доступность и не удаляет ответы. Отдельно проверить истечение тарифного периода: публичный доступ и новый RSVP закрываются независимо от даты события.
