# E1-06 · Миграционный слой и тестовая БД

**Review после локальной проверки; hosted CI проверяется отдельно.** Зависимости E1-02/05 приняты в main `4f7394d`; D-27 согласовал Prisma. Источники: [NFR-14/15](../povod-mvp-spec-v0.1.md), [backend-правила](../architecture/backend-conventions.md), [backlog](backlog.md). Команды и границы — [инструкция](../operations/database-migrations.md), факты — [QA](../qa/e1-06-report.md).

Один PR: точные Prisma/client/adapter-pg, явная первая SQL-миграция, фабрика клиента, повторяемый синтетический seed, защищённые local dev/test scripts, Vitest на реальном PostgreSQL и изолированный job CI. Ведущий владеет общими scripts, lockfile и workflow. Продуктовые сущности/identity/Swagger/HTTP readiness/серверные релизы не входят. Поля технической таблицы не являются частью публичного API.

Критерии:

1. Чистая установка по lockfile, генерация без DB/env, typecheck приложения и тестов, build и текущие unit-тесты успешны.
2. Committed migration создаёт только техническую database_probe; повтор migrate deploy безопасен и не меняет историю.
3. Seed на явном dev/test создаёт одну синтетическую запись, повтор не дублирует её.
4. Test-target проверяет loopback, БД, роль, отсутствие URL override, явный marker и реальную identity/privileges до записей; dev/remote/admin/missing marker отклоняются. Reset/drop-all нет.
5. Интеграционные тесты проверяют реальную уникальность и rollback; удаляют только собственный случайный ID, не чужие данные.
6. CI создаёт отдельные контейнер/роль/БД, повторяет migration/seed, запускает тесты; отказ job должен запрещать успешный required Build kit.
7. Изолированный build-комплект содержит generated runtime и committed SQL/schema; smoke проверяет загрузку Prisma/adapter без исходного node_modules. База не нужна для root liveness.

Результат останавливается на ревью. Принятие владельцем и merge отдельно; production migrations не запускаются этими local-only scripts.
