# V2-03 · Обработка заявок

FR-24, R2-03/05/09/10. [ТЗ](../povod-mvp-spec-v0.1.md) · [Очередь администратора](v2-03-admin-request-queue.md) · [Предпросмотр и заявки](owner-preview-and-requests.md).

- Администратор может начать обработку новой заявки и отклонить новую или уже просматриваемую заявку. Отклонение требует подтверждения. Состояние «В работе» относится к заявке в целом и не назначает исполнителя.
- `PATCH /api/v1/admin/requests/{id}/status` принимает `status` и `expectedVersion`. Требуются сессия, роль администратора, разрешённый Origin и CSRF. Перед записью роль проверяется в транзакции. Успешный ответ содержит только ID, статус и версию заявки.
- Повтор того же перехода с прежней версией подтверждает уже применённое действие, если состояние совпадает. Другой переход с устаревшей версией возвращает 409. Закрытую заявку через этот маршрут открыть снова нельзя.
- Владелец видит статус открытой заявки и последнюю закрытую заявку, когда открытой нет. После отказа доступна новая подача. Черновик и его ревизия сохраняются. Контактные данные не возвращаются в ответе владельца.
- Причины отказа и полная история остаются отдельно. Переход в «Завершена» добавляется вместе с фактической публикацией. Миграции для изменения статуса не нужны.

Для проверки запустите `npm run dev:api:database` и `npm run dev:web`. Создайте заявку из предпросмотра. В отдельной сессии администратора откройте `/admin/projects`, начните обработку и подтвердите отклонение. Обновите предпросмотр владельца и проверьте статус отказа и доступность формы новой заявки.

Локально прошли 172 общие и 225 API/БД-проверок, типы, сборки, форматирование и повторная генерация Orval. В Chrome с тестовым PostgreSQL подтверждены обработка, отказ и повторная подача. Новая заявка получила ревизию 5, прежняя сохранила статус REJECTED.
