## Реальный browser/API/PostgreSQL

Отдельный Chrome headless с отдельным профилем, собственный API на свободном порту, **test-БД**, отдельный файловый inbox. Запросы только тестового профиля направлены к собственному API через Chrome/CDP; web — локальный Next dev. Пользовательские процессы web/API не остановлены, dev-аккаунт владельца не изменён. Синтетические User/pending/reset и счётчики прогонов удалены после проверки; коды, пароли и cookies в отчёт не включены.

| Исходные данные | Действие | Наблюдаемый результат |
| --- | --- | --- |
| Новый email | Register → код | User отсутствует до confirm; экран кода без поля пароля |
| Неверный/прежний код | Confirm, затем resend | 400 и понятная ошибка; прежний код не работает, новый работает |
| Валидный код | Confirm регистрации | User.emailVerifiedAt установлен, вход, безопасный account query/hash сохранён |
| Подтверждённый email | Повтор register | 409 с переходами к login/reset |
| Существующий аккаунт | Request reset → resend → код/новый пароль | Нейтральный экран; старый код отклонён; новый завершает смену |
| Сохранившийся независимый сеанс | Успешный reset | Нет неотозванных Session владельца; старый cookie → 401 |
| Завершённый reset | Перейти ко входу | Автовхода нет; прежний пароль → 401, новый → account |
| Неизвестный email | Request reset | Тот же нейтральный экран, без раскрытия существования аккаунта |
| Открытый шаг кода | Reload / сменить email | Возврат к началу, старый пароль не восстановлен |

## UI fixtures и визуальная проверка

422 с field path, 429 с Retry-After=2, 503 старта, неопределённый confirm, заведомо истёкший expiresAt — **симулированные ответы для UI**, не доказательство соответствующего server behavior. Проверены связь email error с полем, disabled/countdown, сообщение без ложного успеха, отсутствие автоматического повторного confirm. Backend реальные лимиты/истечение/гонки покрыты прежними integration suites.

Проверены 360 px, desktop, RU/EN, light/dark, отсутствие горизонтального overflow, code input/focus, leading-zero fixture, подсказки нового пароля, пустые состояния и сообщения успеха. На просмотренных снимках исправлен контраст primary в dark через `--identity-on-brand`; поддерживаемые поля/правила вынесены в entity identity. Найденный hydration mismatch aria-pressed переключателя темы исправлен: состояние браузерной настройки применяется после mount. Браузерная консоль проверяется отдельно от native Network-записей отказов API.

Снимки и машинный отчёт — локально `.verification/identity-web/`, игнорируются Git, содержат только синтетические данные. Полный аудит a11y/браузеров и автоматизированный CI E2E не выполнены.
