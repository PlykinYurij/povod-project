Ссылка advisory на upstream #194 проверена отдельно: она ведёт к открытому PR с заголовком о leading `?` в extglob. Он не является опубликованным исправлением этой advisory. Нельзя автоматически считать произвольный upstream commit патчем и подменять им npm-пакет.

## Реальная экспозиция в текущем репозитории

`package.json`: unit-команда — `vitest run scripts/artifact`; `apps/api/vitest.integration.config.mts`: статический include `apps/api/tests/**/*.integration.test.mts`. `scripts/database.mjs` запускает зафиксированный config. В исходниках приложений не найдено прямых импортов picomatch/tinyglobby или передачи HTTP-полей в glob API. Следовательно, по проверенному текущему коду путь от пользователя сайта к уязвимому matcher не обнаружен. Это статическая оценка границ, не полноценный security-аудит всех зависимостей.

PR может менять тесты/config и выполнять произвольный код: его нельзя считать доверенными данными только потому, что риск здесь относится к glob. В `.github/workflows/ci.yml` уже заданы hosted disposable runners, contents: read, persist-credentials: false и timeout 15 минут для каждого job. Event — pull_request, не pull_request_target. Прямых ссылок secrets.* в workflow нет; БД тестовая. Это ограничивает последствия зависания CI, но не исправляет ReDoS и не делает чужой PR безопасным для запуска локально с доступами владельца.

## Варианты и рекомендация для владельца

1. **Рекомендуется временно сохранить pins и существующие ограничения:** не принимать glob из пользовательских данных, не запускать недоверенные PR локально с секретами, CI остаётся в изолированных hosted runners с timeout. Остаточный риск — зависание тестового процесса/расход CI в пределах ограничения, в том числе при изменении конфигурации. Общий audit остаётся красным. Это предложение принятия ограниченного риска, **ещё не решение владельца**.
2. Downgrade Vitest до 3.1.4, предложенный npm, — существенная смена тестового стека; сам номер не доказывает отсутствие транзитивного picomatch. Не выполнен.
3. Override/fork/локальный patch — требует проверенного исправления, сопровождения и проверки npm advisory; сейчас такого выбранного патча нет. Не выполнен. Не подавлять advisory как «исправленную» через изменение порога audit.

Пересмотр: не позднее **25.11.2026**, а также при публикации patched release или до появления любого потребителя недоверенных glob. Это дата ручного контрольного шага, автоматическое напоминание не настроено. Перед публичным выпуском повторить audit; если появится исправление, отдельный PR с точными pins/lockfile, clean npm ci, типами/сборками, artifact unit, DB/HTTP и Windows/Linux kit.
