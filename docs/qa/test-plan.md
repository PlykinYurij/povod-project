# План проверки и матрица критичных сценариев

Статус: технические T-01–06 выполнены для E1-01, подробности и границы — [отчёт](e1-01-report.md). Продуктовые P/R остаются Planned, их приложение ещё не поддерживает. Приоритет: [решения D-01–27](../product/decisions.md), затем [исходные FR/NFR](../povod-mvp-spec-v0.1.md#6-функциональные-требования-и-критерии-приёмки). Первоначальный план QA/DevOps подготовлен до реализации; его сценарии ниже не следует считать всеобщим Passed.

Обозначения: **Р** — ручная/браузерная проверка, **И** — интеграционная с настоящей изолированной БД/HTTP/worker, **E** — E2E через браузер. Для гонок полезнее И, для пути и сообщений — один E плюс Р; не копировать каждый backend-тест в E2E. Свидетельство: SHA, версии/среда, синтетические данные, действие, ожидаемый и фактический результат, команда и exit code либо отчёт/снимок. Фактический статус T — в отчёте; P/R пока Planned.

## До dev и публичного запуска

Операционные проверки — [release-plan](../operations/release-plan.md). Нужны доказательства изоляции dev/prod (NFR-15), идентичного SHA/digests (NFR-16), неуспешной миграции/отката и восстановления БД/медиа (NFR-11/12). Производительность NFR-03–05 проверяется после фиксации устройства/сети/кеша/смеси запросов Q-12; доступность — по согласованному перечню экранов. Контроль паролей, CSRF, URL и загрузок NFR-07–09 — негативными запросами, не одной зелёной E2E.

Q-19 (purge-delay/restore/export после soft-delete), Q-09 (старые фото-URL), Q-04 (форма), Q-16 (whitelist), Q-11 (повторы/TTL) блокируют соответствующие кейсы, не каркас. Окончательную очистку нельзя проверять по выдуманному сроку. Q-10/правовая проверка обязательны до реальных данных. План не означает, что исключения FR/NFR приняты владельцем.
