# E4-01b · Приёмка снятия в интерфейсе

Объём — снятие действующего приглашения администратором, состояние после операции и возврат редактора. Возобновление относится к следующей поставке. [Карточка](../product/e4-01-publication-lifecycle.md) · [Макет](../design/publication-lifecycle.md)

Проверен [c8f14fc](https://github.com/PlykinYurij/povod-project/commit/c8f14fc423eb0d641c674476f85dc20d7b833908) с API [6ab9a23](https://github.com/PlykinYurij/povod-project/commit/6ab9a232e6fe7d7f1253a268d4027dbceaba312b). Ревью нашло недоступное обновление после закрытия диалога с конфликтом и лишнюю форму первичной заявки после снятия. Оба замечания исправлены, независимое повторное ревью прошло.

- Сборка web прошла. До исправлений ревью полный web-набор прошёл в одном worker, 184 теста. После исправлений семь целевых тестов подтвердили входные поля, повтор того же запроса, конфликт, отказ в доступе и видимость первичной заявки.
- Chrome, локальный API и синтетический сопровождаемый проект. На 360 px администратор выбрал паузу и указал причину. После сохранения запись аудита содержала выбранный режим, причину и ID действующего администратора. Старый гостевой адрес вернул 404, подписи формы RSVP и причина снятия отсутствовали на гостевой странице. При 1440 px администратор открыл редактор снятого проекта.
- Режим продолжающегося срока, сценарии других ролей и конкурентный переход покрывает серверная приёмка. Повтор после неопределённого ответа и обновление после конфликта проверены в компонентных тестах.

Для ручной проверки в [локальной среде](../../README.md) войди администратором, открой опубликованный сопровождаемый проект в кабинете и сохрани его гостевой адрес. Нажми «Снять с публикации», явно выбери режим и укажи причину. После подтверждения проверь фактический статус в кабинете, недоступность прежней ссылки в гостевом окне и доступность редактора. Не используй для такой проверки реальные приглашения.
