# E1-01 · Фактические проверки

Дата: 11 ноября 2026. Ветка `feat/monorepo-skeleton`, база `origin/main` — `387d161`. Отчёт относится к изменению в этом PR; итоговый SHA сообщается при публикации, чтобы не создавать самоссылку коммита. Среда: Windows PowerShell 5.1, Node 26.13.0, npm 11.20.0, локальный Chrome. E1-00 pins/peer-проверка — [toolchain](../operations/toolchain.md).

Статус этапа **Review**, не принят владельцем и не слит в main. Проверки провёл ведущий; это самопроверка интеграции, не независимая QA-приёмка. Web/API/дизайн выполняли три субагента в разделённых областях файлов; общий контракт/manifest/lockfile вёл один интегратор.

Дополнительно: production start обоих приложений при уже занятом соответствующем порте завершился с exit 1. Прямой запуск API с PORT=invalid завершился с exit 1. Dev API-watch после runtime-ошибки ожидает изменений; это отдельно объяснено в README и не выдано за успешный запуск.

Первоначальная установка с Nest CLI выявила 5 low/moderate предупреждений его dev-цепочки. CLI удалён, заменён tsc + Node watch/ts-node; итоговая установка сообщает **0 известных уязвимостей** по ответу registry на дату проверки. Это не общая гарантия безопасности. `npm audit fix --force` и несовместимые overrides не применялись.

## Макеты — отдельное свидетельство

Дизайнер актуализировал три существующих файла без правок продуктового кода. Ведущий повторил Chrome selftest после последней CSS-правки: PASS для seed, запрета публикации без проверки адреса, доступного адреса, блокировки при processing, text-only после публикации и нуля сопровождающих при отказе. Повторно проверены viewport editor360, confirm390, guest390, confirm1440: переполнения нет; скриншот confirm390 дополнительно просмотрен ведущим. Остальные дизайн-скриншоты просмотрел дизайнер. Нет browser Runtime/console/Log errors.

Проверка HTML не доказывает реальную публикацию/RSVP. Значения/состав полей Q-03/04/16 остаются предложениями. Figma не использовалась: целевой файл и разрешение записи не предоставлены. Vowee повторно не исследовался.

## Что не проверено и что дальше

Финальная проверка документов: локальные пути Markdown-ссылок в 40 файлах существуют (якоря отдельно не проверялись), конфликтных маркеров нет, inline JavaScript макета синтаксически корректен. SHA-256 исходного ТЗ неизменен: `276fbfd4fc094f8b1a4f8d77351370efb24b634568409d54f47f25dff1c578ac`. Diff просмотрен; `git diff --check` прошёл после удаления лишней пустой строки. Итоговый `npm audit --audit-level=low --fetch-retries=0 --fetch-timeout=15000` — exit 0, 0 vulnerabilities; `npm ls --depth=0` — exit 0. Все созданные для запуска проверок web/API процессы остановлены, listening на портах 3000/3001 после проверки отсутствует.

Нет реализации авторизации, БД/изоляции владельцев, медиа, snapshot/publish, 90-дневного жизненного цикла, RSVP/квот, XLSX, admin, i18n, CI/CD и внешнего размещения; P/R-кейсы не выполнялись. Нет unit/E2E/lint scripts; Vitest и ESLint/Prettier ещё не подключены. Тест, копирующий константу health, намеренно не добавлялся по карточке.

Linux/macOS, другие браузеры, нагрузка, полная доступность, ручной Ctrl+C и graceful shutdown под Windows отдельно не проверялись. API tsc-build не очищает старый dist: сборка из чистых входов проверена; политика чистого артефакта относится к E1-07. Временные harness/копия/скриншоты в игнорируемой `.verification` не входят в коммит, команды для приёмки находятся в [README](../../README.md).

После приёмки владельцем и merge ближайшая отдельная задача — E1-02, CI уже существующих typecheck/build; E1-05 PostgreSQL требует выбора local-способа Q-07. Следующий этап в этой ветке не начат.
