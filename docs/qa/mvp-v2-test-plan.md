# Проверки MVP v2 · План, не результаты

Источники: [MVP v2](../product/mvp-v2.md), [FR/R2-критерии](../product/acceptance-criteria.md), [архитектура](../architecture/assisted-publication.md). Старые T/P/R identity/draft/upload/RSVP проверки сохраняются в относящейся части; P-07–14 с самостоятельной публикацией пересматриваются. Самопроверка документации не независимое QA-ревью.

| Сценарий | Исходные данные | Действие | Ожидаемый результат / метод |
| --- | --- | --- | --- |
| Типизированная форма | Garden v1 и иной шаблон | Ввести допустимые/чужие поля, отключить optional | Concrete TS/Orval и runtime DTO согласованы, неизвестные поля 422; typecheck + HTTP + component |
| Каталог/цена | Разные категории/price versions | Фильтр, открытие демо, изменение цены | Карточка/заявка не используют чужую цену/версию; политика Q-27; API+browser |
| Owner-заявка | Клиенты A/B, проект A | B подставляет projectId A, A отправляет верную revision | B нейтральный 404, A получает заявку, сайт не публикуется; HTTP/PG |
| Заявка без проекта | Контакты, projectId отсутствует | Submit и технический повтор | По Q-24 auth/anti-spam, одна заявка, нет фиктивного Project/User; HTTP/PG |
| Privacy/RBAC | Admin и обычный клиент | Queue/detail/status и попытка role=admin при регистрации | Клиент не повышает роль/не читает чужие контакты; admin по scope, no-store; HTTP/browser |
| Отзыв admin | Сессия ранее была административной | Отозвать роль, вызвать publish | Действие запрещено без перевхода/устаревшего role cache; PG/HTTP |
| Admin-assisted | Общая заявка без проекта | Создать проект дважды с тем же key | Одна связь/request/project, creator/customer по Q-25, нет фиктивного email; PG/HTTP |
| Дрейф данных | Оператор посмотрел revision N | Другая вкладка сохранила N+1, admin публикует N | Никакой неявной публикации новых данных, конфликт/повторное согласование Q-28; PG/browser |
| Цена изменилась | Клиент видел priceVersion V | Обновить каталог до V+1, отправить/публиковать заказ | Принятая Q-27 политика, нет молчаливой подмены/нулевой цены placeholder; HTTP/browser |
| Клиент пытается publish | Сессия клиента, валидные данные | Вызвать admin publish/назначение домена | 403, никаких snapshot/period/address/fulfilled; PG/HTTP |
| Два оператора | Одна согласованная заявка | Одновременный publish тем же/разными ключами | Одна публикация/receipt, повтор безопасен, audit actors понятен; PG/HTTP |
| Гонка адреса | Два проекта/заявки | Admin публикуют один slug | Один успех, второй 409; request не ложно fulfilled, период не выдан второму; PG/HTTP |
| Сбой до commit | Готовая заявка | Ошибка внутри publish transaction | Ни адреса, ни периода, ни fulfilled частично; PG fault injection |
| Ответ потерян | Publish commit выполнен | Повторить тот же key/body | Прежний receipt/URL, не новый срок/снимок; PG/HTTP |
| Гостевая privacy | Snapshot и контакты в заявке | Получить HTML/public API/OG и submit RSVP | Только публичные поля, нет телефона/мессенджера/owner/draft; SSR/HTTP/browser |
| Анимация/доступность | Сложный оригинальный renderer | Mobile/keyboard/reduced-motion/медленное устройство | Контент/RSVP доступны, эффекты не блокируют; browser/performance по NFR/Q-12 |
| Две формы | Форма заказа и RSVP | Submit RSVP | Только ответ гостя, не ServiceRequest; HTTP/PG |
| Миграция | Старые users/session/projects, 14 copy/null/Unicode | Накатить новые каталоги/роли/выбранное хранение | Сохранены данные/ревизии, обычные user не admin, старые версии рендерятся; isolated PG/migration |

Незакрытые Q-23–32 не подменяются ожидаемыми значениями в тестах. До первого real publish необходимы media-ready, небольшая форма RSVP и политики адреса/срока. В этой документационной задаче новые продуктовые тесты, нагрузка, browser E2E приложения и production не выполнялись.
