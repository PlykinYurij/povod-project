## Что проверяется

| Исходные данные / действие | Ожидаемый и проверяемый результат |
| --- | --- |
| Открыть форму, выбрать тему/язык | Компактная кнопка только с SVG луны/солнца; select RU/EN без видимой подписи; aria-label и Tab-доступ сохранены |
| Ввести email `test` в login/register/reset и отправить | Красная ошибка под email, связь aria-describedby; native invalid event/tooltip не возникает, запрос не отправляется |
| Начать ввод нового пароля | Шесть постоянных пунктов под input, красные невыполненные / зелёные выполненные с разными символами и доступным статусом; пользовательского текста ASCII нет |
| Ввести корректный пароль с пробелом / без него | Пункт «Без пробелов» переключается; новые пароли с пробелами отклоняют клиент и сервер |
| Ввести разные повторные пароли | Красная ошибка под подтверждением; нет register/reset confirm запроса. После совпадения ошибка уходит |
| Register с именем → resend → confirm → session/login | Имя сохранено в pending, затем в User и response; account обращается по имени. До кода User отсутствует |
| Пройти reset и войти снова | Имя сохранено, повтор пароля проверен, обычный вход новым паролем работает |
| Существующий User/pending без имени | Миграция сохраняет null, старая заявка подтверждается, login не требует имени; прежний пароль с пробелами принимается |
| 422/400/409 из API | Известные ошибки полей показываются под полями, без дублирующего alert. Сеть/503/429 остаются общими ошибками формы |

## Выполнено

Добавляющая nullable-миграция `20261119010000_identity_display_name` применена root `db:migrate:dev` и `db:migrate:test`. Данные не сбрасывались. Реальные HTTP/PG проверки: **55/55**; в том числе пустое/null/число/слишком длинное/многострочное имя, trim, resend, перенос в User/session, старая pending-запись и старый пароль с пробелами. Обновление reset DTO также проверено на запрет пробелов.

Сквозной Chrome/CDP прогон с отдельным профилем, собственным API, test-БД и отдельным inbox прошёл все строки UI-матрицы: живой список правил, несовпадение/совпадение, inline email/code/credentials, сохранение имени после reset, обе темы/RU/EN, 360 px, Tab. Счётчик native invalid events = 0. Нет необработанных JS-исключений и console.error React, включая reload в dark. Снимки просмотрены: `.verification/identity-review/registration-desktop-empty.png`, `registration-mobile-en-dark-rules.png`, машинный `report.json`; артефакты локальные и игнорируются Git. Пользовательские серверы не останавливались, dev-аккаунт не менялся; свои fixtures очищены.

Через shared/ui добавлен узкий адаптер PasswordInput: Mantine 9.8.1 ставит data-invalid, адаптер также передаёт aria-invalid настоящему input и включает доступность reveal по Tab. Это исправление доступности, не собственный UI-kit.

Проверки: `npm test` **53/53**, `npm run test:web` **43/43**, `npm run typecheck`, `npm run build`, `npm run format:web` успешны. `npm run api:openapi` и `npm run api:generate` успешны; повтор генерации воспроизвёл generated-клиент без изменений (проверка SHA-256 дерева). Проверены локальные Markdown-ссылки, неизменность исходного ТЗ, отсутствие конфликтов/локальных credentials и `git diff --check`.

Не проверены SMTP/production, полный аудит a11y/всех браузеров, новый isolated release kit и rollout на внешний сервер. CI нового коммита оценивается отдельно после push. Offline HTML-макет identity — предыдущая итерация до D-34; фактический web и данный отчёт описывают актуальную форму. Источник ТЗ не меняется.
