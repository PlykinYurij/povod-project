# Ключевые проектные решения и развилки

A-01 в части шаблона/места принят D-14; прочие технические A — **предложено для ревью**, не изменение решений владельца. Исходники: [D-01–13](../product/decisions.md), [ТЗ §9](../povod-mvp-spec-v0.1.md#9-техническая-архитектура).

| ID | Предложение и причина | Компромисс / альтернатива |
| --- | --- | --- |
| A-01 | Общая схема Wedding Garden v1 и один версионированный рендерер для preview/public. Детали в [контракте](api-contract.md) | Название+адрес обязательны как конкретизация «места»; онлайн-событие/только маршрут потребуют изменения схемы до фиксации |
| A-02 | Частичный черновик с optimistic revision, полный неизменный снимок на публикации | Конфликт вкладок видим и требует сверки; last-write-wins проще, но теряет данные |
| A-03 | NestJS — единственный источник прав/срока/квоты; модульный монолит + PG | Меньше дублирования; Next зависит от API для каждой публичной выдачи |
| A-04 | Публикация атомарна с местом, периодом и receipt; блокировка владельца перед проектом | Сериализует конкурирующие публикации одного аккаунта, зато не даёт третьего места и двойного периода |
| A-05 | Visibility, расход периода, slotOccupied и contentLocked различны | Больше явных полей/инвариантов, зато D-07/10/11 не пытаемся выразить одним archived |
| A-06 | SSR/no-store сначала; публичный id с достаточной случайностью и noindex | Проще отзыв новых открытий, больше нагрузка. Кеш допускается после замеров/отдельного решения. Медиа TTL остаётся открытым |
| A-07 | Multipart через API, private S3 и PG-job worker, готовые версии immutable | Меньше сложности presigned uploads; API обслуживает поток файлов, нужны лимиты и backpressure. Redis не добавляется |
| A-08 | Локальные поля даты/времени события и IANA-пояс для отображения; период — UTC сервера | Не решаем UTC события/DST, пока оно не управляет действиями; соблюдает D-13 |
| R-01 | Отклонено D-16: RSVP уже в v1 | FormVersion фиксируется при первой публикации |

## Не превращённые в правила допущения

- Сохранять выбор шаблона после входа и ввод при исправимой ошибке — UX-предложения.
- Точные длины полей, один hero-блок, палитры sage/sand и состав программы — проект первого шаблона, не общее ограничение четырёх шаблонов. Полный MVP ещё требует остальных трёх.
- В примере 90 дней — исключительно демонстрация. Длительность бесплатного периода — Q-15; лимиты фото/черновиков приняты D-15.
- D-17 разрешает только текстовые исправления после публикации; whitelist ещё Q-16. Каждое исправление — новая immutable-версия без изменения права публикации.

## Оставшиеся решения владельца

90 дней и объект удаления согласованы D-19/20. Требуются: задержка до окончательной очистки, право восстановления/экспорта после soft-delete Q-19; whitelist текстов Q-16; поля фиксированной формы Q-04. Место освобождается при истечении, пауза удерживает его. Политики бэкапов/медиа Q-10/09 остаются до реализации удаления.
