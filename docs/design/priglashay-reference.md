# Референс «Приглашай онлайн» · 20.11.2026

Изучены публичные страницы, а не административный интерфейс. Источники проверены web-доступом и отдельным изолированным Chrome; открытая вкладка владельца не использовалась. Для Computer Use в этой сессии отсутствует node_repl, поэтому просмотр выполнен самостоятельным браузерным процессом. Контактные формы не заполнялись и не отправлялись.

## Что действительно доступно

| Страница | Наблюдение | Использование в «Поводе» |
| --- | --- | --- |
| [Каталог](https://priglashyonline.ru/) | Категории событий, карточки с ценой, просмотр демо и заказ; альтернативный путь консультации. В описанном процессе сначала заявка, затем общение и подготовка материалов | Категория → цена → демо; два явных пути «Заполнить самому» и «Помогите создать» |

| [Юбилей](https://priglashyonline.ru/yobiley) | Декоративный фон, выразительная типографика, данные события и анкета; в runtime присутствуют анимационные элементы | Разные шаблоны могут иметь разные композиции/анимации при общем контракте renderer |

На каталоге также доступны категории и ссылки демо гендер-пати; сами такие демо в этот проход визуально не проверялись. Музыкальные controls видны; воспроизведение/лицензии аудио не исследовались. Числа цен, доплаты, срок до даты события и чужие коммерческие условия не переносятся в наши правила.

## Визуальное покрытие и ограничения

Посмотрен первый экран каталога 1440×1000; первые экраны «Гармонии» и юбилея и секция RSVP в эмуляции mobile viewport 390×1000, innerWidth=scrollWidth=390. Вёрстка свадебного демо — фотообложка, светлые секции, serif-текст; у юбилейного — тёмный декоративный фон. Это наблюдения выбранных экранов, не полная оценка всех шаблонов/всех браузеров. Анимации обнаружены в DOM, их полные сценарии/производительность/reduced-motion не измерены. Текстовые страницы исследованы шире первого экрана; всю страницу визуально за один снимок не выдаём.

Первоначальный narrow desktop capture имел несоответствие CSS viewport, поэтому мобильные выводы сделаны только после явной device metrics эмуляции. Снимки и диагностические данные лежат в ignored .verification; чужие фото/шрифты/код не добавлены в приложение или публичные assets репозитория.

Не проверены и не приписываются референсу: аккаунты клиентов, внутренний редактор, БД, admin, actual delivery заявок, публикационные операции, оплата, приём RSVP и уведомления. Недоступность некоторых страниц для web-parser компенсирована браузерным чтением двух указанных демо; закрытая часть не исследовалась.

## Предлагаемый UX «Повода»

- Карточка: событие/название/цена, «Посмотреть пример», «Создать своё». Демо не маскируется под уже созданный проект.
- Авторизованный путь: форма → сохранение → реальный private preview → «Отправить на публикацию». Кнопка ведёт к заявке, а не сообщает о публикации.
- Контакты заявки: имя, телефон, предпочтительный канал Telegram / MAX / VK и способ найти человека в выбранном канале. Правило contactValue для каждого канала согласовать, не полагаться на один телефон для всех платформ.
- Успех: номер/статус заявки и дальнейшие шаги; публичную ссылку показывать после реального admin publish. Никаких обещаний срока ответа из чужого сайта.
- Общая заявка: помощь с созданием без подготовленного проекта; необходимость входа пока Q-24. Не заставлять клиента выбирать фиктивный проект.
- Admin: очередь → карточка/контакты → проект и preview → согласованная версия → назначить адрес → подтвердить публикацию. Для заявки без проекта — «Создать проект по заявке».

Предстоит отдельный пакет desktop/mobile макетов: каталог с ценами/категориями, форма проекта, preview, заявка/успех/ошибки, клиентский статус, admin list/detail/create/publish. Старый [first-flow.html](first-flow.html) показывает прежнюю самостоятельную публикацию и не является актуальным UX этой операции. Identity-макеты и оригинальный «Тихий сад» сохраняются. Финальные макеты этой задачей не созданы.
