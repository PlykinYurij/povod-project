# «Конфетти» · день рождения

E5-01a, макет для ревью. [Открыть автономный макет](birthday-confetti.html) · [План](development-plan.md) · [Backlog](../product/backlog-v2.md)

Крупное имя именинника, сиреневая обложка, цветные карточки события и геометрическое конфетти, нарисованное CSS. Приглашение использует системные шрифты, композиция статична. Порядок неизменен. Обложка → дата и место → фото → заметка → подтверждение участия → подпись. На узком экране карточки даты и места располагаются друг под другом. Фото, заметку и подпись можно пропустить. Длинные строки переносятся, включая подпись кнопки.

## Предлагаемый тип данных

Категория дня рождения, версия `birthday-confetti-v1`. Реестр версии связывает строгий JSONB, пресеты, редактор и гостевой рендерер. [D-36, D-37 и D-40](../product/decisions.md) · [Эволюция схемы](../architecture/template-schema-evolution.md)

| Раздел | Поля | Правила черновика и публикации |
| --- | --- | --- |
| Проект и язык | `title` вне JSONB, `content.locale` | Название до 24 символов. Локаль `ru` или `en`, исходная `ru`. Управляет `lang`, форматом даты и служебными сообщениями независимо от кабинета. Авторский текст сохраняется как введён |
| Обложка | `celebrantName`, `copy.invitationLabel`, `copy.intro` | Имя до 20 символов необходимо к публикации. Подпись категории и вступление редактируются, могут быть пустыми |
| Событие | `event.date`, `event.startTime`, `event.timeZone`, `venue.name`, `venue.address`, `copy.whenHeading`, `copy.whereHeading`, `copy.dateLabel`, `copy.timeLabel` | К публикации необходимы дата ISO, время HH:mm, часовой пояс IANA, название места до 80, адрес до 150. Значение даты не управляет сроком публикации |
| Фото | `photo.mediaId` (UUID или null), `photo.alt`, `copy.photoHeading` | При null секция скрыта. Для публикации проверяется готовое фото текущего проекта. Описание редактируется, пустое допустимо для декоративного фото |
| Заметка | `note.enabled`, `note.heading`, `note.body` | Показывается при включении и непустом тексте. Выключение сохраняет введённые данные |
| RSVP и подпись | `copy.rsvpHeading`, `copy.rsvpIntro`, `copy.rsvpAction`, `copy.signoff` | Подпись кнопки обязательна к публикации и редактируется. Пустой финальный текст скрывается. Публичная форма использует согласованные поля имени, ответа и числа сопровождающих. В предпросмотре отправка недоступна |

Отправная точка для общих пределов D-37 — короткие подписи до 80, заголовки до 160, вступление до 4000 и финал до 1000 Unicode code points. Для новых полей предлагаем `photo.alt` до 200 и заметку до 1000. Черновик допускает пустые обязательные поля, полнота проверяется отдельно при публикации. Тексты отображаются как текстовые узлы. Если автор убирает заголовок, скрывается сам элемент и заменяется ссылка на него в `aria-labelledby` на краткое локализованное имя сохранившейся секции.

## Состояния и передача

- Переключатель вне полотна показывает все блоки, пустой черновик, отсутствие дополнительных блоков, длинные строки, обработку фото и ошибку. В рабочем рендерере загрузка и ошибка фото используют служебные сообщения, а остальное приглашение остаётся доступным.
- Каталог и текущий гостевой путь требуют отдельного подключения версии. В рендерере показ фото должен использовать разрешённый display-ресурс, а в JSON хранится внутренний идентификатор. Публикацию выполняет администратор после проверки содержимого. [Архитектура](../architecture/assisted-publication.md)
- Цена берётся из каталога, сумма остаётся предметом Q-27. [Открытые вопросы](../product/open-questions.md)
- При реализации проверить 360 и 1280 px, увеличение текста до 200%, клавиатуру, длинную подпись RSVP без пробелов, выбор версии в каталоге, соответствие редактора предпросмотру и отправку ответа только по публичной ссылке.
