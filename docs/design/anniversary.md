# «Письмо о юбилее» · E5-01b

[Открыть автономный макет](anniversary.html). Приглашение оформлено как личное письмо на тёплой бумаге. Крупный заголовок набран антиквой, дата выделена винным цветом. На широком экране дата стоит рядом с письмом, фото и заметка складываются в редакционные полосы. На телефоне блоки читаются сверху вниз. Рисунок паспарту выполнен в CSS, используются системные шрифты. Композиция статична. [План дизайна](development-plan.md) · [Второй свадебный шаблон](second-wedding.md)

Порядок блоков фиксирован: письмо и дата → место и время → фото, если выбрано → заметка, если включена и заполнена → RSVP → подпись. На панели над полотном доступны шесть проверочных состояний. Она предназначена для просмотра макета. В реальном предпросмотре состояние приходит из редактора и обработки медиа.

## Предлагаемый контракт версии

Кандидат `birthday-anniversary-v1`, категория дня рождения. `content.locale` принимает `ru` или `en`, начальная локаль русского пресета `ru`. Локаль управляет форматированием даты, служебными сообщениями и HTML `lang` независимо от кабинета. Авторский текст хранится без автоматического перевода и отображается как обычный текст. [D-36, D-37, D-40](../product/decisions.md) · [Версии шаблонов](../architecture/template-schema-evolution.md)

| Блок | Поля | Правило |
| --- | --- | --- |
| Проект и письмо | `title` проекта вне JSONB, `celebrant`, `copy.eyebrow`, `copy.letter` | Для публикации нужны название проекта и имя. Надзаголовок и письмо можно оставить пустыми |
| Дата, место и время | `event.date`, `event.startTime`, `event.timeZone`, `venue.name`, `venue.address`, `copy.dateLabel`, `copy.placeHeading` | Для публикации нужны дата ISO, время HH:mm, IANA-пояс, название и адрес. Дата события используется для отображения |
| Фото | `photo.mediaId` UUID или null, `photo.alt`, `copy.photoHeading`, `copy.caption` | Null скрывает блок. Загрузка и ошибка media отображаются внутри выбранного блока. Для публикации проверяются принадлежность к проекту и готовность медиа по общему контракту |
| Заметка | `note.enabled`, `note.text`, `copy.noteHeading` | Выключенная заметка скрыта, введённый текст сохраняется при переключении. Если текст пуст, блок скрыт |
| RSVP и подпись | `copy.rsvpHeading`, `copy.rsvpIntro`, `copy.rsvpAction`, `copy.signoff` | Подпись кнопки обязательна к публикации. Поля ответов и серверная обработка общие. В предпросмотре кнопка отключена |

Для общих полей предлагаем ориентир D-37 в Unicode code points. Название проекта — 24, имя — 20, место — 80, адрес — 150, короткие подписи и CTA — 80, заголовки — 160, письмо — 4000, подпись — 1000. Для новых полей предлагаются 200 для alt, 240 для подписи фото и 1000 для заметки. Обязательные поля могут быть пустыми в черновике. Пределы и имена полей этой версии подлежат проверке при согласовании разработки. Цена приходит из каталога, сумма ожидает решения Q-27. [Открытые вопросы](../product/open-questions.md)

## Состояния и приёмка

- Длинные имена, адреса и подписи RSVP переносятся. Проверить 360 и 1280 px, увеличение текста до 200% и клавиатурное управление переключателями макета. Статичная композиция сохраняется при системном предпочтении reduced motion.
- Пустой черновик получает служебные подсказки на языке приглашения. Если авторский заголовок пуст, рендерер убирает видимый заголовок и использует соответствующее служебное имя для оставшейся секции. Пустые необязательные секции пропускаются целиком. Для декоративного фото используется пустой alt.
- Смена варианта макета показывает наличие и отсутствие дополнительных блоков, обработку и ошибку фото. В приложении неверная или недоступная фотография оставляет читабельными письмо, данные события и RSVP. Гостевой рендерер выбирается по версии, выдача фотографии использует медиа, связанное со снимком.
- Для реализации нужны отдельные DTO, пресет, форма и рендерер этой версии, подключённые к общим каталогу, редактору, предпросмотру и публикации. Уже сохранённые версии других шаблонов продолжают использовать свои схемы. Право публикации остаётся у администратора.

В макете вымышленные данные и CSS-заглушка фото. Проверки реального фото, записи RSVP, серверной валидации и каталога относятся к реализации.
