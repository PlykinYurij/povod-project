# План макетов

Исполнитель работает в отдельном checkout с cwd `docs/design`. Читать [локальные инструкции](AGENTS.md), [порядок ревью](../agent-workflow.md), [существующие макеты](README.md), [FR/NFR и критерии](../product/acceptance-criteria.md), [решения](../product/decisions.md), [вопросы](../product/open-questions.md), [API](../architecture/api-contract.md), [web-правила](../architecture/web-conventions.md).

Уже есть low-fi HTML первой вертикали, описание сценария и traceability. Это исходная основа, а не завершённый UI всех функций. Ни один новый результат ниже не отмечен принятым. «Пакет» — часть родительской карточки backlog, не новый продуктовый ID. Одно поручение/PR на пакет; родительскую E0-02 не закрывать по одному экрану.

Для каждого пакета: экраны desktop/mobile, поля/обязательность/лимиты, loading/empty/error/success, переходы, RU/EN где применимо, клавиатура/focus, связь с API и FR/NFR. Артефакты — автономный локальный HTML/CSS с синтетическими данными и описание; без сетевых шрифтов/картинок/скриптов. Приложение в apps/web дизайнер не создаёт. Figma-перенос отдельно, только при точном файле и подтверждённом доступе.

Три галочки: выполнен пакет и ручные проверки с записью доказательств → явное принятие владельцем → проверен результат в main, записан SHA. После пакета остановиться на ревью. UI-реализация зависит от принятого соответствующего пакета, а не от принятия сразу всех макетов.
