# «Вдвоём» · второй свадебный шаблон

E5-01, эскиз для реализации и отдельной приёмки владельцем. [Открыть автономный HTML](second-wedding.html). Синий первый экран, две пересекающиеся золотые арки и кремовая страница с контрастными разделителями. Арки нарисованы CSS и скрыты от вспомогательных технологий. Используются системные шрифты. При отключённой анимации сохраняется вся композиция. [План дизайна](development-plan.md) · [Тихий сад](quiet-garden.md)

На широком экране имена и рисунок стоят рядом, а дата и место делят строку. На узком экране все секции идут вертикально. Порядок фиксирован: обложка → дата и место → фото при наличии → пожелания при наличии → RSVP → подпись. Длинные имена, адрес и слова переносятся. Гость видит приглашение на языке заполненного контента, служебные состояния принадлежат платформе.

## Поля для согласования контракта

Кандидат — отдельная версия `wedding-together-v1` для существующей категории свадьбы. Строгая схема JSONB, DTO, пресет, форма и renderer регистрируются под новым идентификатором. Garden v1 и его опубликованные снимки остаются совместимыми. [D-36, D-37 и D-40](../product/decisions.md) · [Эволюция шаблонов](../architecture/template-schema-evolution.md)

| Раздел | Поля | Требования при публикации |
| --- | --- | --- |
| Проект и обложка | `title` вне JSONB. В контенте `names.first`, `names.second`, `copy.heroLabel`, `copy.separator`, `copy.intro` | Название проекта и два имени обязательны. Тексты и соединитель редактируемы и могут быть пустыми |
| Событие | `event.date`, `event.startTime`, `event.timeZone`, `venue.name`, `venue.address`, `copy.eventHeading`, `copy.dateLabel`, `copy.venueLabel` | Дата, время, часовой пояс, название места и адрес обязательны. Дату отображает рендерер, она не управляет сроком публикации |
| Фото | `photo.mediaId` UUID или null, `photo.alt`, `copy.photoHeading` | Блок необязателен. Null скрывает весь блок. При наличии медиа проверить готовую обработанную версию, связанную с проектом. `photo.alt` — редактируемое описание, пустое подходит для декоративного фото |
| Пожелания | `note.enabled`, `note.heading`, `note.body` | Блок необязателен. Если выключен или текст пуст, весь блок скрывается. Сохранённый текст можно вернуть включением блока |
| RSVP и финал | `copy.rsvpHeading`, `copy.rsvpIntro`, `copy.rsvpAction`, `copy.signoff` | Тексты принадлежат приглашению. CTA опубликованной страницы всегда доступна по имени, при пустой подписи редактор требует заполнение. Контракт ответов гостя переиспользуется, предпросмотр не принимает ответов |

Для общих полей отправная точка — пределы D-37 по Unicode code points: название проекта 24, каждое имя 20, место 80, адрес 150, соединитель 16, обложка и короткие подписи 80, вступление 4000. Предложенные пределы новых текстов: заголовки 160, описание фото 200, пожелания и подвал 1000, подпись CTA 80. Черновик принимает пустые значения обязательных полей. При публикации сервер проверяет заполненность и типы. Дата использует ISO YYYY-MM-DD, время HH:mm, часовой пояс IANA. Модель цены и версию цены берём из каталога. Сумма зависит от Q-27. ## Передача в разработку

- Редактор использует поля версии, допускает пустой черновик и сохраняет введённое при ошибке. Все авторские подписи, включая CTA, задаются пресетом и редактируются. Технические подсказки о пустом черновике и медиа переводятся через i18n.
- Предпросмотр отображает пустые обязательные данные, загрузку и сбой медиа без запроса к публичному RSVP. На гостевой странице обработанное фото загружается из текущего публичного снимка. При сбое выдачи изображения остальные секции остаются доступны.
- Проверить 360 и 1280 px, 200% увеличения, клавиатуру, reduced motion, скрытие невключённых секций, длинные поля, цену из каталога и работу RSVP в опубликованной версии. Проверить, что публикация не открывает редактирование, а после снятия шаблон остаётся прежним.

Макет использует вымышленные данные, CSS-рисунок и заглушку фото. Переключатели находятся вне гостевого полотна. Реальное медиа и отправка RSVP проверяются после реализации в приложении. Внешние материалы для эскиза не нужны. Q-14 о пользовательских наблюдениях остаётся открытым.
