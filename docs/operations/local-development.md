# Локальная разработка: план

Статус: E1-01 реализован, актуальный проверенный порядок запуска — [корневой README](../../README.md), результаты — [QA-отчёт](../qa/e1-01-report.md). Ниже сохранён план следующих операций; слова об отсутствии команд в первоначальном разделе первой задачи относятся к состоянию до реализации. Факты проверены 11 ноября: Windows/WebStorm/PowerShell 5.1, Node 26.13.0 и npm 11.20.0 доступны. Наличие Corepack больше не требуется. Docker ранее не найден в PATH, WSL не проверен.

## Первая задача

Выбран npm workspaces решением D-23, отменяющим прежний pnpm. Каркас работает в текущем Windows/PowerShell без WSL/Docker/БД. Входной инструментальный шаг и версии — [first-task](../product/first-task.md). Сейчас не выполнять установки или изменение системных настроек.

Будущий разработчик:

1. Получает отдельную рабочую копию и проверяет версии Node/npm по README.
2. Выполняет workspace-установку зафиксированным npm, используя корневой lockfile. В чистой копии проверяет npm ci без изменения lockfile.
3. Открывает два PowerShell-терминала WebStorm в документированных каталогах, запускает реальные scripts web/API.
4. Открывает локальный web, проверяет GET `/health`, выполняет typecheck и production-сборки обоих приложений.
5. Останавливает процессы и повторяет по README. Результаты T-01–06 фиксируются с SHA/версиями, не обещаются заранее.

Предлагаемые порты каркаса: web 3000, API 3001. До реализации это проектные значения, а не доказательство свободных портов. Конфликт порта должен давать понятную ошибку; README описывает реально поддержанный способ смены. `/health` — root-liveness, бизнес-API позже `/api/v1`. `.env`/секреты каркасу не нужны. Отсутствие БД не маскируется фиктивной readiness.

Команд dev/typecheck/build сейчас нет. Исполнитель создаёт минимальные реальные scripts, запускает их и записывает точный порядок/порты/ответы в README и AGENTS. Не переносить команды из генератора без проверки. PowerShell 5.1 не предполагает Bash, `export` или поддержку `&&`. Глобальный Next/Nest CLI не требуется; локальные версии фиксируются.

## После каркаса

Выбор способа PostgreSQL/S3/Mailpit и Docker/WSL — перед E1-05 и зависимыми задачами, отдельно от E1-01. Предпочтение ТЗ — WSL2+Docker; фактическую установку/работу ещё надо проверить. Если переносим работу в WSL, clone и node_modules должны быть в одной Linux-среде; не использовать Windows node_modules из WSL.

PostgreSQL: отдельные dev и test БД/роли. Test-runner проверяет явный test-маркер/роль и отказывает destructive-cleanup при dev/prod connection string. Миграции и вымышленные seed появляются отдельным PR; ни schema push в production, ни очистка пользовательских данных не являются обычным запуском тестов.

Медиа: локальный S3-совместимый сервис/отдельные test-префиксы; Mailpit или эквивалентный перехватчик без внешней доставки. `.env.example` только с названиями и безопасными примерами, реальные env вне Git. Каждый сервис добавляется с реальным потребителем, smoke и остановкой; пустой Compose «на будущее» не нужен в каркасе.

## Среды и изоляция

| Свойство | Local | Закрытый dev/staging | Production |
| --- | --- | --- | --- |
| Цель | Разработка | Приёмка точного SHA | Пользователи |
| Данные | Синтетические | Только синтетические | Реальные после допуска |
| Доступ | localhost | Дополнительная авторизация на входе | Публичный сервис, защищённый кабинет |
| БД | Dev и отдельная test | Своя БД/роль/доступ | Своя БД/роль/доступ |
| Медиа | Local/test namespace | Отдельный bucket/ключи | Отдельный bucket/ключи |
| Секреты | Локальные вне Git | Только dev-доступы | Только prod-доступы, агент без deploy-key |
| Почта | Перехватчик | Перехватчик/строгий allowlist | Принятый провайдер |
| Сборка | Локальные проверки | Проверенный комплект SHA/digests | Те же digests, без пересборки |

Label «dev» не является изоляцией: dev технически не должен читать prod-ресурсы. Префикс допустим только при подтверждённой IAM-изоляции, проще разные buckets. Тестовый код не получает prod-env. Одно VPS возможно лишь после оценки: отдельные сети/volumes/роли/ресурсы, общие ядро и диск остаются точкой отказа. Никаких провайдеров, цен, доменов или готовых доступов здесь не предполагается.
