# Приватное хранилище фото

Дайте приложению API доступ к отдельному приватному бакету окружения. Для него требуются переменные `MEDIA_S3_ENDPOINT` (точный origin без пути), `MEDIA_S3_REGION` и `MEDIA_S3_BUCKET`. Аутентификация использует стандартную цепочку AWS SDK. Для локального тестового провайдера задайте синтетические отдельные ключи через стандартные переменные SDK. Секреты остаются в локальном окружении API, а не в frontend или Git.

Используется path-style PUT без публичного ACL. API поддерживает HTTPS и локальный HTTP на 127.0.0.1 вне production. Три настройки читаются при первом использовании. При отсутствии конфигурации запрос создания фото получит 503, а существующие функции приложения продолжат работать. Объекты лежат под `projects/<id>/photos/<id>/original`. Их нельзя отдавать напрямую гостям.

После `npm run db:migrate:dev` запустите `npm run dev:api:database` из окружения с настройками. Приём HTTP multipart описан в Swagger и [карточке E2-03](../product/e2-03-photo-intake.md). Для проверки без внешнего аккаунта `npm run test:database` после сборки использует реальный SDK, синтетические данные и контролируемый S3 HTTP-стенд на loopback. Этот тест проверяет подпись, путь и тело PUT. Перед dev-развёртыванием отдельно проверить совместимость выбранного бакета с PUT и checksum SDK.

В каждом экземпляре API одновременно буферизуются до двух загрузок. Для dev и production нужно установить лимиты тела и времени запроса на прокси.

После `npm run db:migrate:dev` и `npm run build --workspace @povod/api` запустите `npm run worker:photos:database` в отдельном терминале с теми же настройками приватного хранилища. Команда использует локальную dev-БД. `npm run worker:photos` использует явный `DATABASE_URL` и подходит для процесса окружения после миграции. Worker требуется доступ на GET оригинала и PUT производных. Ctrl+C останавливает опрос, затем процесс завершает текущую попытку и закрывает подключения.

Готовые версии находятся под `projects/<id>/photos/<id>/renditions/<токен готовой попытки>/`. Живой токен хранится в PostgreSQL. Другие токены содержат частичные или отброшенные результаты. Операции очистки и безопасная выдача производных идут в E4-03 и E2-03c соответственно. [Карточка worker](../product/e2-03b-photo-worker.md).
