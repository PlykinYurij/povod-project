# Локальная приёмка регистрации и восстановления

Продолжение [входа/навигации](web-sign-in.md). [Карточка](../product/e1-04-identity-web.md), [QA](../qa/e1-04-identity-web-report.md), backend: [регистрация](registration-confirmation.md), [сброс](password-reset.md).

При работающем локальном PostgreSQL и применённых dev-миграциях, из корня в двух терминалах:

```powershell
npm run dev:api:database
```

```powershell
npm run dev:web
```

Открыть `http://127.0.0.1:3000`. Использовать именно этот hostname для web/API; API ожидает точный Origin. Если старый API уже занимает 3001, остановить его в его терминале перед запуском helper. `dev:api` без настроенной БД не заменяет `dev:api:database`. Порт 15432 — PostgreSQL, это не HTTP-страница.

1. Главная → кабинет → вход → «Зарегистрироваться». Ввести имя, синтетический email, новый пароль и его повтор. Шесть правил под полем отмечаются при вводе; пробелы запрещены. Ошибки email/имени/паролей отображаются под полем, браузерных всплывающих сообщений нет. После 202 откроется поле шести цифр, пароль исчезнет с экрана. В кабинете ещё нет нового владельца.
2. Локальных настоящих писем нет: открыть соответствующий свежий JSON в игнорируемой `.local-mail` через WebStorm; сверить `to`, `purpose: registration` и срок. Ввести `code` в форме. Не публиковать письмо или код в issue/скриншоте. Успех → кабинет с данным email.
3. Выйти → «Забыли пароль?» → тот же email. В новом письме `purpose: password-reset` взять код, указать новый пароль и его повтор. Успех сообщает об отзыве сеансов, не входит автоматически. Перейти ко входу, проверить новый пароль; старый отклоняется.
4. Проверить неверный код, resend (старый больше не действует), смену email и reload (сценарий начинается заново). Письмо/код живут 10 минут, пять ошибок исчерпывают код; UI не знает оставшихся попыток. Ограничения писем/API действуют и локально, Retry-After определяет ожидание. Не превращать ручные повторы в бесконечный retry.
5. Проверить RU/EN (select без видимой подписи), тёмную/светлую тему (иконки луны/солнца) и мобильную ширину. Сохранённая тёмная тема после reload не вызывает hydration mismatch.

Перед локальной приёмкой обновления D-35 выполнить `npm run db:migrate:dev`: сначала добавляются nullable display_name (D-34), затем миграция 20261119020000_identity_user_name переименовывает их в user_name без удаления значений. На уже обновлённой локальной БД повтор команды ничего не меняет. При новых API/типах старый запущенный процесс может потребовать обычного перезапуска в его терминале. [QA доработок](../qa/identity-code-review-report.md).

Кодовые шаги используют `/register` и `/password-reset`, без секретного контекста в URL. После перезагрузки введите email/пароль заново по подсказке. Неясный ответ confirm может означать завершённое действие: сначала попробуйте обычный вход с выбранным паролем.

Команды проверок: `npm run typecheck`, `npm test`, `npm run test:web`, `npm run format:web`, `npm run build`. Backend regression: `npm run test:database` при готовой test-БД. OpenAPI generation: `npm run api:generate`, diff generated должен отсутствовать. Новые lint/E2E команды не добавлены; браузерный прогон в QA выполнен локальным инструментом Chrome/CDP и пока не включён в CI.

Это локальный файловый inbox, не SMTP и не публичная регистрация. Production без почтового транспорта закрыт; ограничения D-33, legacy Q-22 и юридические решения остаются отдельными условиями запуска.
